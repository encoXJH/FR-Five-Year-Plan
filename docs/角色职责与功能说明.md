# 五年计划指标管理平台角色职责与功能说明

> 适用版本：2026 年 11 月当前版本  
> 适用对象：平台管理员、校级负责人、建设方向负责人、学院项目负责人  
> 编写目的：明确各角色“负责什么、能做什么、能看哪些数据、在流程中处理哪一步”，用于账号配置、人员培训和日常操作。  
> 业务口径：现行新流程为 **A 类指标 → 学院 B 任务**；历史 A+ 数据仅用于兼容查看，不再新建。

## 一、角色体系总览

| 角色 | 角色代码 | 适用人员 | 核心职责 | 默认数据范围 |
| --- | --- | --- | --- | --- |
| 平台管理员 | `ADMIN` | 发展规划处、系统管理人员 | 建计划、配指标、管组织账号、分解下发、年度核算、系统运维和全局监督 | 全校数据 |
| 校级负责人 | `LEADER` | 分管校级负责人、相关决策人员 | 查看全校进度、审批调整终审、查看材料和操作日志 | 全校数据 |
| 建设方向负责人 | `SCHOOL_OWNER` | 每条 A 类指标的建设方向负责人 | 维护本人指标、分解下发、审核学院填报、发起及初审调整 | 本人负责的 A 及其下属 B |
| 学院项目负责人 | `UNIT_OWNER` | 各执行单元指定的任务负责人 | 查看本单元任务、填报完成值、上传佐证材料、确认接收转入任务 | 本单元 B 及相关指标、计划 |

### 1.1 角色与负责人不是同一概念

- **角色**决定账号具有哪些功能权限。
- **A 指标负责人**决定建设方向负责人能管理哪些指标、审核哪些学院填报。
- **B 任务负责人及所属执行单元**决定学院项目负责人能处理哪些任务。
- **主要建设方向总负责人**只是责任关联，必须选用具有校级负责人角色的用户，但不新增角色、审批节点或额外数据范围。

### 1.2 多角色规则

一个账号可以同时拥有多个角色，例如既是建设方向负责人，又是学院项目负责人：

- 功能权限按所有角色的**并集**计算；
- 可见数据也按各角色范围合并；
- 不需要在页面上手动切换“当前角色”；
- 服务端会重新校验每个接口的权限和数据范围，隐藏菜单不能替代安全控制。

## 二、平台管理员

### 2.1 主要责任

平台管理员负责平台从初始化到核算归档的全过程管理，是系统配置和业务流程的主要维护者。

1. 维护执行单元、用户、角色、专业群、字典和系统参数。
2. 新建、复制、启动、归档计划，管理计划模板。
3. 配置主要建设方向、方向负责人和 A 指标归属。
4. 录入、导入、修改 A 类指标，检查量化口径、目标和材料要求。
5. 将可量化 A 分解为学院 B，保存草稿、预览并下发任务。
6. 激活年度，组织年度核算、解锁、补做管理和五年核算。
7. 必要时代填、代审，处理目标调整和其他调整事项。
8. 查看全校统计、大屏、材料库和操作日志，并导出日志。

### 2.2 功能清单

| 功能模块 | 可执行内容 | 注意事项 |
| --- | --- | --- |
| 首页与计划管理 | 新建、复制、编辑、启动、归档计划；另存或管理模板 | 归档后计划只读；执行数据不会因复制计划而复制 |
| 指标总表 | 新增、编辑、删除未下发指标；Excel 导入；设置年度目标 | 已下发目标不能直接覆盖，须走调整审批 |
| 指标认定 | 对 MANUAL 汇总指标填写人工认定值和说明 | 年度未激活、已锁定或计划已归档时不能写入 |
| 分解下发 | 选择学院、指定 B 负责人、填写逐年目标、保存草稿和下发 | 承接单元必须已启用且具备“可承接新 B”资格 |
| 任务代填 | 代学院填写完成值、上传材料并提交 | 代填属于敏感操作，必须填写原因 |
| 审核中心 | 查看待审记录、预览材料、通过、驳回、核减和批量通过 | 驳回必须填写意见；认定值不能大于填报值 |
| 调整管理 | 发起延期、转移、延期加转移；发起目标调整；处理权限范围内审批 | 目标调整仅管理员可发起；审批全部通过后才生效 |
| 年度管理 | 激活年度、年度核算、解锁、查看缺口和补做结果 | 解锁必须填写原因；核算前先处理待审核填报 |
| 五年核算 | 规划期结束后执行五年核算并查看达标结果 | 当前年份须晚于规划结束年，且全部年度已锁定 |
| 统计与大屏 | 查看全校年度、五年累计、学院和指标进度 | 统计仅包含当前权限和业务规则允许的数据 |
| 材料库 | 检索全校材料、上传并关联指标材料、预览和下载 | 学院填报材料仍须审核通过后才进入材料库 |
| 操作日志 | 查询全部日志、查看变更前后内容、导出日志 | 日志只能追加，不能修改或删除 |
| 系统管理 | 管理执行单元、用户角色、专业群、方向、字典、参数和飞书配置 | 修改角色等敏感操作必须按页面要求填写原因 |

### 2.3 典型工作顺序

**基础配置 → 新建计划 → 维护方向和指标 → 分解下发 → 激活年度 → 跟踪填报审核 → 年度核算 → 五年核算与归档。**

## 三、校级负责人

### 3.1 主要责任

校级负责人以全局监督和最终审批为主，不负责日常指标维护、任务填报或学院任务分解。

1. 通过统计报表和可视化大屏掌握全校建设进度。
2. 查看各执行单元、各指标的完成值、完成率和达标情况。
3. 对延期、转移、延期加转移及目标调整进行最终审批。
4. 查看全校佐证材料和操作日志，追溯重要业务变化。
5. 可作为主要建设方向总负责人，但该身份不增加新的审批环节。

### 3.2 功能清单

| 功能模块 | 可执行内容 | 数据范围与限制 |
| --- | --- | --- |
| 首页与计划概览 | 查看计划、年度进度和指标完成情况 | 全校只读查看 |
| 统计报表 | 查看年度和五年累计统计、学院排名、指标明细 | 全校数据 |
| 可视化大屏 | 查看整体进度、完成率、学院对比、指标进展和预警 | 全校数据 |
| 调整审批 | 查看申请原因、附件、调整前后快照和前置审批意见；同意或驳回 | 仅处理到达校级负责人审批节点的申请 |
| 材料库 | 检索、预览和下载佐证材料 | 全校只读，不直接上传或绑定指标材料 |
| 操作日志 | 查询日志并查看变更前后内容 | 全校查看，无日志导出权限 |
| 待办与消息 | 处理待审批事项，查看结果通知 | 与本人相关的待办和通知 |

### 3.3 审批重点

- 调整原因是否充分，附件是否能够证明调整必要性；
- 转出、接收及目标年度是否符合规划期；
- 调整数量是否超过尚未完成量；
- 建设方向负责人是否已初审，转移类是否已由接收学院确认；
- 调整前后目标是否守恒，是否存在重复冻结或重复申请；
- 任一环节驳回后，本次申请即结束，不再进入后续节点。

## 四、建设方向负责人

### 4.1 主要责任

建设方向负责人是 A 类指标的业务责任人，负责把指标转化为可执行任务，并对学院填报真实性和完整性进行审核。

1. 维护本人负责的 A 指标及年度目标。
2. 将可量化 A 分解到学院，指定学院负责人并下发。
3. 对 MANUAL 汇总指标进行人工认定。
4. 审核本人指标下各学院提交的完成值和佐证材料。
5. 对权限范围内任务发起延期或转移申请，并负责调整初审。
6. 查看本人负责指标的统计、进度、材料和业务记录。

### 4.2 功能清单

| 功能模块 | 可执行内容 | 数据范围与限制 |
| --- | --- | --- |
| 指标总表 | 新增或编辑指标、设置量化口径和年度目标、导入指标 | 仅本人负责的 A 及其任务；不能管理他人指标 |
| 分解下发 | 保存学院分工草稿、预览和下发 B 任务 | 仅本人负责范围；下发前须通过目标和负责人校验 |
| 人工认定 | 对 MANUAL 汇总 A 填写年度认定值和说明 | 仅本人负责指标，受年度和归档状态限制 |
| 审核中心 | 筛选待审记录、预览材料、通过、驳回、核减和批量通过 | 仅本人负责指标下的学院填报 |
| 调整申请与初审 | 发起延期、转移、延期加转移；处理建设方向负责人初审 | 不能发起目标调整；不能代替校级负责人终审 |
| 统计报表 | 查看年度和五年累计完成情况及指标明细 | 以本人负责指标及其 B 为主 |
| 材料库 | 检索、上传并关联指标材料、预览和下载 | 仅本人负责指标的材料 |
| 待办与消息 | 处理待审核、待初审等事项 | 与本人负责范围相关 |

### 4.3 审核要求

- 审核前核对任务、年度、统计口径、填报值和完成情况说明。
- 在线查看佐证材料，不能只根据填报数值直接通过。
- 核减后的认定值不能大于填报值，核减或驳回必须写明意见。
- 只有审核通过的数据才计入完成值、统计报表和材料库。
- 年度已锁定或计划已归档时不能继续审核。

## 五、学院项目负责人

### 5.1 主要责任

学院项目负责人是本单元 B 任务的执行责任人，核心是按期、按口径完成填报并提供可核验材料。

1. 查看本学院已下发任务、五年目标、年度目标和完成进度。
2. 在当前自然年且年度已激活时填写完成值。
3. 上传佐证材料，保存草稿、提交审核、撤回未审核填报。
4. 根据驳回意见修改后重新提交，查看历次填报和审核记录。
5. 对转移类调整进行接收确认或拒绝，并填写处理意见。
6. 查看本单元统计和材料，完成未达标任务的补做确认。

### 5.2 功能清单

| 功能模块 | 可执行内容 | 数据范围与限制 |
| --- | --- | --- |
| 学院工作台 | 查看本单元任务、筛选年度和状态、进入填报与任务详情 | 纯学院角色登录后默认进入该页面 |
| 任务填报 | 新建或修改草稿、提交审核、审核前撤回、驳回后修改重报 | 仅本单元、当前自然年、已激活且未锁定任务 |
| 佐证材料 | 随填报上传材料，查看提交记录中的材料 | 材料须审核通过后才进入材料库 |
| 调整接收确认 | 对转入本单元的任务确认接收或拒绝 | 仅转移类调整的接收方处理；当前版本不能主动发起调整 |
| 补做处理 | 查看待补做记录，在补做实际完成后确认完成 | 仅本单元记录，并受业务状态限制 |
| 统计报表 | 查看本单元年度和五年累计完成情况 | 不能查看其他学院任务明细 |
| 材料库 | 检索、预览和下载本单元已入库材料 | 不直接通过材料库绑定指标材料 |
| 待办与消息 | 查看待填报、驳回、转入确认和结果通知 | 与本人及本单元相关 |

### 5.3 各统计口径的填报内容

| 统计口径 | 学院应填写的内容 | 不应填写的内容 |
| --- | --- | --- |
| 增量累计型 | 本次新增数量 | 不要把历年累计量当作本次新增量 |
| 存量时点型 | 当前最新总量 | 不要只填本次增加量 |
| 增长率型 | 当年实际总量 | 不直接填写增长率，由系统计算 |
| 占比型 | 分子和分母 | 不直接填写本学院百分比 |
| 直填百分比型 | 百分比、来源说明和佐证材料 | 不能缺少来源说明；至少上传一份材料 |
| 是否型 | 是否完成，可按页面要求补充完成日期和说明 | 不填写普通数量 |

### 5.4 填报状态处理

- **草稿**：可继续修改或删除，尚未进入审核。
- **待审核**：内容只读；尚未审核时可撤回后修改。
- **已通过**：认定值计入完成值，不能重复覆盖提交。
- **已驳回**：根据审核意见修改完成值或材料后重新提交。
- **年度锁定、计划归档或历史任务**：只读，不再填报。

## 七、跨角色业务流程分工

### 7.1 计划与任务执行流程

| 顺序 | 业务环节 | 主责角色 | 配合或后续角色 | 结果 |
| :-: | --- | --- | --- | --- |
| 1 | 基础数据与账号配置 | 平台管理员 | 各角色提供人员和负责人信息 | 执行单元、用户和权限可用 |
| 2 | 建设计划、方向和指标 | 平台管理员 | 建设方向负责人核对本人指标 | 形成计划指标体系 |
| 3 | 指标量化与学院分工 | 平台管理员、建设方向负责人 | 学院负责人确认实际承接信息 | 形成 B 任务草稿 |
| 4 | 任务下发 | 平台管理员、建设方向负责人 | 学院负责人接收任务通知 | 学院可查看任务及五年目标 |
| 5 | 年度激活 | 平台管理员 | 学院负责人 | 当前年度具备填报条件 |
| 6 | 完成值填报和材料上传 | 学院项目负责人 | 平台管理员可在必要时代填 | 形成待审核填报 |
| 7 | 填报审核 | 建设方向负责人 | 平台管理员可代审 | 通过后计入完成值和统计 |
| 8 | 跟踪进度 | 全部角色按范围查看 | 校级负责人重点监督 | 形成年度和五年累计进度 |
| 9 | 年度核算与补做 | 平台管理员 | 学院负责人完成补做 | 锁定年度并记录达标结果 |
| 10 | 五年核算与归档 | 平台管理员 | 校级负责人及相关负责人核对 | 完成规划期闭环 |

### 7.2 指标调整流程

| 调整环节 | 负责角色 | 主要处理内容 |
| --- | --- | --- |
| 发起申请 | 平台管理员或建设方向负责人 | 选择任务和类型，填写数量、年份、接收单元、原因及附件；目标调整仅管理员发起 |
| 试算校验 | 发起人和系统 | 核对未完成量、冻结额度、目标守恒、接收资格和调整前后结果 |
| 建设方向负责人初审 | 建设方向负责人 | 核实业务原因、材料、数量和目标变化；通过或驳回 |
| 接收学院确认 | 接收方学院项目负责人 | 仅转移类需要；确认是否承接转入任务 |
| 校级负责人终审 | 校级负责人 | 核对全流程意见和快照，作出最终审批 |
| 调整生效 | 系统自动处理 | 全部通过后在一个事务中更新目标、保存快照、记录日志并通知相关人员 |

**任一审批环节驳回，本次申请即结束。审批中的调整额度会冻结，避免重复申请；申请撤回后按规则释放。**

## 八、所有角色共同遵守的规则

1. **按数据范围操作**：不能通过修改页面地址或记录 ID 查看他人、其他学院数据。
2. **只读状态不可写入**：历史任务、已锁定年度和已归档计划不能继续填报、审核或调整。
3. **当前自然年限制**：学院只能填报服务器当前自然年的数据，历史记录可查看。
4. **年度激活限制**：年度未激活不能填报，年度已锁定不能填报或审核。
5. **审核通过才计入成绩**：草稿和待审核数据不计入完成值、统计或材料库。
6. **重要操作留痕**：写操作、导出和文件下载按规则记录操作日志；敏感操作须填写原因。
7. **并发修改保护**：页面提示“数据已被修改”时，应刷新并核对最新内容后再提交，不要连续重复操作。
8. **菜单不是安全边界**：看不到按钮可能是无权限，也可能是当前业务状态不允许；最终以后端校验为准。
9. **移动端使用边界**：手机重点支持学院工作台、任务填报和待办消息；复杂分解、批量审核建议电脑操作。

## 九、账号配置与日常检查清单

### 9.1 管理员配置账号时

- [ ] 用户姓名、工号、所属执行单元和启用状态正确。
- [ ] 角色选择正确；一人多角色时已按需勾选。
- [ ] A 指标已绑定正确的建设方向负责人。
- [ ] B 任务已绑定正确的学院项目负责人。
- [ ] 执行单元已启用，并按业务需要设置“可承接新 B”。
- [ ] 使用对应账号抽查计划、指标、任务和材料可见范围。

### 9.2 建设方向负责人开始工作前

- [ ] 能看到本人负责的计划和 A 指标。
- [ ] 指标口径、年度目标、学院分工和材料要求正确。
- [ ] 审核中心只出现本人负责范围的填报。
- [ ] 调整初审中的任务确属本人负责范围。

### 9.3 学院项目负责人开始填报前

- [ ] 当前计划、学院和年度正确。
- [ ] 任务已下发，当年已激活且未锁定。
- [ ] 已理解该任务统计口径，没有混用新增量、总量或百分比。
- [ ] 佐证材料完整、清晰、可核验。
- [ ] 提交后关注审核结果，驳回后按意见修改重报。

### 9.4 校级负责人审批前

- [ ] 已查看调整原因、附件和前后快照。
- [ ] 已核对校级初审及接收学院意见。
- [ ] 调整未突破规划期、剩余量和目标守恒规则。
- [ ] 对异常进度、未达标或频繁调整事项已安排后续督促。
