## 二、数据库与数据访问

1. **禁止修改 V1 已执行的表结构**；后续变更一律新增 V3+ 迁移脚本。
2. **不用 `@TableLogic`**：`deleted` 字段语义为「0 未删除 / 删除时写本行 id」（配合带 deleted 的唯一索引避免与历史数据冲突），与 MP 逻辑删除的 0/1 语义不同，查询一律手工 `eq("deleted", 0)`。
3. **Long ID 序列化**：雪花 ID 以字符串传给前端，逐字段加 `@JsonSerialize(ToStringSerializer.class)`，不做全局 Long→String（避免误伤 version 等数值字段）。
4. **时间序列化**：自定义 `JacksonConfig`，`LocalDateTime` ↔ `yyyy-MM-dd'T'HH:mm:ss+08:00`。**踩坑**：序列化时用 `appendLiteral("+08:00")` 拼时区字面量；直接用 `appendOffset` 会在无 offset 的 `LocalDateTime` 上抛异常。
5. **逻辑外键不建物理外键**，引用一致性由应用层保证（数据库设计决策）。
6. 表分包：`system / plan / indicator / task / submission / adjustment / milestone / file / audit / notify / integration`。
7. 配置全部走环境变量（`application.yml` 只放默认值，不落真实密钥，仓库不提交密钥）。
8. 数据源 URL 补 `createDatabaseIfNotExist=true`：V1 内含 `CREATE DATABASE metrics_db` + `USE`，JDBC 直连不存在的库会先失败。

## 四、横切实现约定

1. **统一响应**：`ApiResponse` + `ResponseAdvice`；跳过 swagger、文件流（`InputStreamResource`）、`String` 返回值特判。
2. **错误码**：全量 46 个业务码 + HTTP 映射；JWT 过滤器把 20002/20003 写入 request attribute，入口统一翻译成 20001/20002/20003/20004。
3. **幂等**：`@Idempotent` + AOP 两阶段（占位 → 完成），唯一索引防并发，24h 窗口；重放返回首次结果，`IdempotentReplayException` 走 10004 分支。
4. **审计**：`@AuditLog` + AOP，SpEL 取 `resourceId` / `reason`；审计写库失败不影响主业务。
5. **数据范围**：`DataScopeService`，越权统一 20005。
6. **分页**：`PageQuery`，`sort` 字段白名单防注入；MP 乐观锁 + 分页插件。
7. **单测只写纯逻辑**（JacksonConfig / SignedUrlService / JwtService），删除默认 `contextLoads`（避免测试依赖数据库）。

## 六、联调对齐与 E2E 踩坑（阶段 2 收尾，2026-10-23）

1. **幂等占位插入必须写 `response_status=0`**：V1 `idempotency_record.response_status` 为 NOT NULL 无默认值，阶段 1 的占位插入未赋值，首个 @Idempotent 接口（finalize）E2E 时才暴露为 500。已修：占位 0 → 成功 200。
2. **创建指标时 totalTarget 对所有口径必填**：RATIO 为末年应达比率（小数）、BOOLEAN 固定为 1、GROWTH/STOCK 为末年应达总量；年度目标必须覆盖计划起止每一年且不重复（BOOLEAN 非完成年传 null）。
3. **定稿校验顺序**：完整性（负责人齐全、年度目标完整）先于守恒（40003）；破坏守恒的负例需先保证完整性通过才会命中 40003。
4. **activate / archive 需带 version**（VersionRequest）；finalize 同。
5. **TreeNode 增加 baselineValue / yearTargets / version，APlusSummary 增加 statCaliber**：P04 年度列与编辑抽屉直接消费树数据，避免额外拉详情。
6. **新增 `GET /users/options`**（已登录，返回启用用户 id/name/username）：UI 规范假设 A5 的落地；API 约定 15.10 已补录。
7. **JwtServiceTest 篡改用例去抖**：改为确定性改签名段中间一位（原「末两位改 xx」有约 1/256 概率仅改动 base64 填充位导致解码字节不变而漏判）。
8. **PS5.1 Invoke-RestMethod 中文请求体双重编码**（12 字中文入库变 36 字）：E2E 脚本断言一律避免中文匹配，按 code/id 断言；生产前端 axios 无此问题。
9. 前端 `IndicatorDetail.children` 类型为 `Indicator[]`，实际后端返回 APlusSummary 子集（字段够用，阶段 3 如需严格类型再收紧）。

## 八、端到端验收踩坑（2026-10-23）

1. **JDBC `characterEncoding` 必须写 Java 字符集名 `UTF-8`**，写 `utf8mb4` 会被 mysql-connector-j 9.7 直接拒绝（`Unsupported character encoding`）；MySQL 侧仍自动走 utf8mb4。
2. **Windows 子进程会丢弃空值环境变量**：`$env:DB_PASSWORD=''` 传不进 Java 进程，导致回落到默认密码。便携 MySQL 验收时改为把 root 密码设成应用默认值 `Metrics@2026`。
3. 便携 MySQL 启动参数：不能加 `--skip-name-resolve`（root@localhost 将无法匹配 127.0.0.1 连接）；本机已有 MySQL80 服务时必须加 `--mysqlx=OFF`，否则 X 协议端口 33060 冲突。
4. 华为云镜像单流下载约 70KB/s，分段（6 段）并行 + 失败按 Range 续传是可行的加速方案。

## 十一、阶段 3 后端拍板（分解矩阵 / 下发 / 年度激活 / B+ 任务，2026-10-23）

1. **矩阵求和口径**：INCREMENT / STOCK / BOOLEAN 逐年校验「Σ B+ = A+ 当年目标」（下发时 50001）；比率类（GROWTH / RATIO / DIRECT_PERCENT）按 PRD 4.5 注不做求和校验，`isBalanced` 恒 true（summary 仍给出逐年 diff 供展示）。BOOLEAN 矩阵行级规则：每行至多一个计划完成年（<=1 个 1），指标级完成年唯一由平衡校验保证。
2. **保存矩阵推进指标版本号**：PUT allocation 带的是 indicator.version（API 16.3 version 5→6），保存成功后 updateById 推进；下发后（indicator.status=DISTRIBUTED）禁改矩阵，返回 50003。GET allocation 同需 `allocation:edit`（API 15.4 权限列）。
3. **不可下分 A 的矩阵**：只允许 1 行且 unitId 必须等于 indicator.undertakeUnitId；换承接单元先 PATCH 指标（定稿前），矩阵不兼任改 undertakeUnitId 的入口。
4. **下发 expand 语义**：`indicatorIds` 为空 = 全部可下发指标（A+ 与不可下分 A）；传可下分 A = 其全部 A+；已 DISTRIBUTED 的静默跳过（幂等语义），全部已下发时返回 {indicatorCount:0, taskCount:0} 而非 50003。校验链严格 50005 → 50001（errors 逐条 `A01-2.yearTargets[2026]` + 中文明细）→ 50002（errors 逐条任务编号）。A+ 全部下发后所属 A 同步置 DISTRIBUTED。
5. **下发通知**：每条 B+ 给学院负责人生成 notification（type=TASK_DISTRIBUTED、bizType=task、bizId=taskId、feishuStatus=PENDING），飞书推送阶段 8 消费。
6. **确认接收状态机**（PRD 6.2）：DISTRIBUTED → IN_PROGRESS，写 acceptedAt/By；IN_PROGRESS 重复接收幂等返回现状；PENDING_DISTRIBUTION 接收返回 60001（复用「当前状态不允许此操作」，5xxxx 无更合适码，不新增）。accept 带的是 task.version。
7. **年度激活**：`POST /plans/{planId}/years/{year}/activate` 带的 version 是**计划版本号**（与 distribute / finalize 等计划级动作一致）；前置：计划须 ACTIVE（否则 30001）、年度在起止内、LOCKED 返回 60003；重复激活幂等返回现状。激活时该年所有「已下发（DISTRIBUTED / IN_PROGRESS）」任务的 task_year 由 NOT_ACTIVATED → IN_PROGRESS（之后新下发的任务年度行激活在任务接收/年度切换语义外，保持 NOT_ACTIVATED 直到该年激活——下发晚于激活的场景：下发时若该年 plan_year 已 ACTIVE，新任务年度行仍 NOT_ACTIVATED，待 M4 填报前置校验时统一处理，见遗留）。

FOR UPDATE` 锁 adjustment；末环节通过后按 task_year id 升序更新（from −amount / to +amount、`target_version + 1`、释放冻结恢复状态）；延期类同步移动 A+ 的 `indicator_year_target` 年度分布（A+ 总量不变）；转出方全部年度目标为 0 / null 时任务置 TRANSFERRED_OUT；接收方无该 A+ 任务时自动新建（编号 `{A+编号}-{单元编码}`、状态 DISTRIBUTED 待接收确认、owner 取接收单元 id 最小的启用 UNIT_OWNER、可为空、各年 target=0 / original_target=0 / target_version=1、yearStatus=NOT_ACTIVATED 走惰性激活、`source_adjustment_id` 回填）；snapshot_after 按申请时 before + 明细重算（与 preview 同规则）；防御性复核 ΣB+ 逐年 = A+ 逐年（70002 回滚）。
7. **生效复核**：末环节通过时重新校验「目标 − 已完成 ≥ 调整量（不含本单冻结）」（审批期间可能有新审核通过）；不足则 70001 整体回滚（该环节决定不落库，可改走驳回）。年度 LOCKED 校验（60003）在审批处理时执行（规则 7）。
8. **目标调整守恒（70002）**：TARGET_CHANGE 明细项支持 `targetIndicatorId` 配套调整同计划内其他 A / A+；`newTotalTarget` 建模为 `toYear = null` 的明细项落库。校验：INCREMENT / BOOLEAN 年和 = 总量；A+ 逐年 = ΣB+ 逐年；AUTO_SUM 的 A 逐年 = ΣA+ 逐年；比率类不求和。生效时不自动改下属 B+，只校验守恒（不同步分解是 PRD 5.6.1 标注的【P1】能力）。未定稿计划不允许 TARGET_CHANGE（30001，直接编辑即可）。
9. **目标变化后的缓存刷新**：不调用 ActualRecalcService（避免翻动 NOT_ACTIVATED 等非流程状态），改为就地用缓存完成值按新目标重算 `completion_rate / is_achieved / achieve_status`；task_year 仅当状态为 IN_PROGRESS / ACHIEVED 时按新达标结果重判，NOT_ACTIVATED / PENDING_REVIEW / 核算类状态不动。
10. **A 级年度目标不随 B+ / A+ 调整联动**：延期 / 转移只同步到 A+ 的年度分布（数据库设计规则 6.5），A 的定稿目标保持不变；A 为 AUTO_SUM 时 A 与 ΣA+ 的逐年差异由后续年度核算口径消化（A 完成值按 AUTO_SUM 实时汇总，目标保留定稿值）。
11. **快照格式**：`snapshot_before`（申请时写）/ `snapshot_after`（生效时写）均为 JSON 数组，条目 `{taskCode | indicatorCode, year, target}`，`year = null` 表示五年总量条目；preview 与 create / 生效共用 AdjustmentRules.applyMoves / applySetItems 试算，保证一致。
12. **preview 语义**：与 create 走同一 prepare 管线，校验错误收集为 `errors[]` 返回（valid = 无错误）而不抛出；结构性错误（任务不存在 / 计划已归档 / 非管理员发起目标调整）仍直接抛出。
13. **转移类型 toYear 必须等于 fromYear**：跨年移动一律用 POSTPONE_TRANSFER，否则 10001；含延期的类型 toYear 必须晚于 fromYear（70003 文案「早于原年份」扩展为「延期同年也不允许」，属 70003 语义内收紧）。
14. **BOOLEAN 延期**：amount 固定为 1（传其他值 10001）；fromYear 必须是该任务计划完成年（target=1）；生效时 fromYear 目标置 null、toYear 置 1（不用 0，保持 BOOLEAN「完成年存 1、其他 NULL」的存储约定）；该年已完成（actual_value=1）时剩余量为 0，被 70001 拦截。
15. **里程碑 OVERDUE 为展示层换算**：dueDate 已过且状态仍为 NOT_STARTED / IN_PROGRESS 时查询视图按 OVERDUE 返回，不落库；PATCH 置 COMPLETED 自动记 completedAt，移出 COMPLETED 清空。指标级里程碑写操作需 `indicator:edit` 权限码 + 负责人数据范围；任务级按任务数据范围（学院负责人本单元）。DELETE 的 version 走查询参数。
16. **补做完成**：`POST /makeups/{makeupId}/complete`（已补录 API 约定 15.7）权限 `submission:submit`，按任务单元数据范围；完成时 madeUpAmount = gapAmount，来源 task_year MAKEUP_PENDING → MADE_UP；记录生成在阶段 6 年度核算接入。
17. **调整通知**：全部复用 notification 表（feishuStatus=PENDING，阶段 8 推送）；申请提交通知当前环节处理人（ADJUSTMENT_TODO），环节推进通知下一环节处理人，驳回通知申请人，生效通知申请人 + 转出 / 接收任务负责人（ADJUSTMENT_RESULT）。

## 十九、阶段 6 后端拍板（统计 / 年度核算 / 大屏 / 统计导出，2026-10-24）

1. **统计完成率口径统一为「计数制」**：总完成率 / 单元排名 / 方向 / 大屏年度趋势 / 计划卡片 completionRate 一律 = 达标任务数 ÷ 有正目标的年度任务数（`target IS NOT NULL AND target > 0`，BOOLEAN 非完成年 target 为 null 天然不计入），与数据库设计查询 h 一致；ACHIEVED 与 MADE_UP 都算达标，NOT_ACHIEVED 与 MAKEUP_PENDING 都算未达标。不同口径 / 单位的任务完成值不能相加，这是唯一可比的口径。
2. **统计接口的数据范围**：overview / tree 按数据范围（单元 ∪ 本人负责指标）过滤，树中 A / A+ 的数值由可见 B+ 子集按 MetricCalculator 重新汇总（全校用户下与 indicator_year_target 缓存一致，由 StatsConsistencyTest 保证）；by-unit / by-direction 为全校聚合视图，所有登录用户可见（PRD Q12：学院可见全校概览与排名，看不到明细）；trend 是指标级聚合，仅全校角色与指标有效负责人可看，纯学院视角返回 20005。分解矩阵草稿（PENDING_DISTRIBUTION）不计入任何统计。
3. **统计年度解析**：`year` 缺省 = 当前激活年度（多个 ACTIVE 取最大），无激活取最近 LOCKED 年度，再无取起始年；显式传超出计划起止的年返回 10001。
4. **滞后预警**：时间进度 = 年内已过年天数 ÷ 全年天数（年前 0、年后 1）；`时间进度 − 完成进度 > warning.lag.threshold`（V2 种子 0.5，无需新增参数）即预警；只对「已激活未锁定年度 + 进行中（IN_PROGRESS / PENDING_REVIEW / ADJUSTING）+ 有正目标」的年度行判定；计算于读取时，不落库（indicator_year_target.achieve_status 的 LAGGING 暂不写入，避免与审核重算互相覆盖）。预警列表并入 overview（warningCount + warnings），大屏直接复用。
5. **年度核算 settle**：前置 = 计划 ACTIVE（30001）+ 年度 ACTIVE（未激活 60001、已锁定 60003）；带计划版本号；事务内逐 task_year 全量重算（复用 MetricCalculator + 认定值优先口径，与 ActualRecalcService 同规则）并终态化：达标 → ACHIEVED，未达标 → NOT_ACHIEVED，其中 INCREMENT（缺口 = 目标 − 完成值 > 0）与 BOOLEAN（缺口 = 1，PRD 4.4.5）生成 makeup PENDING 记录并置 MAKEUP_PENDING（存量 / 增长率 / 占比 / 直填百分比的缺口无法表达为可补做数量，只记未达标）；补做年度 = min(year+1, 规划末年)（末年缺口记末年本身，表示五年核算后补做）；随后 A+ / 不可下分 A → A 逐级终态化 indicator_year_target（achieve_status 写 ACHIEVED / EXCEEDED / NOT_ACHIEVED，无目标年不动）；未达标任务给学院负责人发 WARNING 站内通知（FR-M6-08）。核算覆盖该计划该年全部已下发任务（含下发晚于激活仍为 NOT_ACTIVATED 的行）。
6. **防重复补做**：重新核算（解锁后再核算）时，来源年度行已有 PENDING / DONE 补做记录的不再生成（CANCELLED 不挡）。
7. **解锁 unlock**：LOCKED → ACTIVE，必填 reason 落 last_unlock_reason + 审计（UNLOCK）；task_year 清 settled_at，NOT_ACHIEVED / MAKEUP_PENDING 回退 IN_PROGRESS，ACHIEVED / MADE_UP 不动；该年未完成的 PENDING 补做记录置 CANCELLED（重新核算时按最新缺口重新生成）。
8. **五年核算 final-settle**：前置 = 全部 plan_year 均为 LOCKED（否则 60001）；逐 A 指标按口径计算五年完成值（INCREMENT 各年之和；STOCK / GROWTH 最后一个有数据年的总量；RATIO / DIRECT_PERCENT 末年比率 / 百分比；BOOLEAN 任一年完成即 1），按达成方向判定五年达标；MANUAL 的 A 末年有人工认定值时以认定值为准； DISTRIBUTED / IN_PROGRESS 任务置 CLOSED；plan 记 final_settled_at / final_settled_by（新增 V4 迁移，只加这两列）；已核算后重复调用幂等返回已生成结果。五年核算结果不建表，查询时由缓存全量重算（数据库设计规则 4：缓存可全量重算）。
9. **V4 迁移**：`V4__plan_final_settle.sql` 仅给 plan 加 final_settled_at / final_settled_by 两列（五年核算标记），不改 V1/V2/V3；无新增表、无新增错误码（复用 30001 / 60001 / 60003 / 10003）。
10. **大屏聚合 GET /screens/{planId}**：一次返回 总览 + 单元排名 + 方向 + 2026–2030 趋势（计数制）+ 调整统计（待审批 / 已生效计数）+ 最近审核动态（最近 10 条 APPROVED / REJECTED 填报，审计日志 plan_id 未落库故取审核动态）；本地 ConcurrentHashMap 缓存，key = planId:year，TTL 120 秒（`app.screen.cache-seconds` / `SCREEN_CACHE_SECONDS` 可配，上限 200 条惰性清理）；screen:view 仅管理员 / 校领导（都是全校范围），缓存无用户维度泄漏；settle / unlock / final-settle 后主动 evict。
11. **STATS_REPORT 导出**：接入现有异步导出框架（export_job + @Async + StorageService 落盘 + 签名下载），params = { planId, year? }；权限 = 管理员 / 校领导 / 校级负责人（PRD P11，纯学院负责人 20004），负责人导出的数据范围在创建时固化 scopeOwner（与 INDICATORS 一致）；报表四个 sheet：总览 / 单元排名 / 建设方向 / 任务明细。AUDIT_LOGS / TASKS / SETTLEMENT 导出类型留阶段 7（审计查询接口 M10 尚未实现，不在本阶段凭空写导出）。
12. **计划列表 completionRate 补齐**（阶段 2 遗留）：与总览同口径（当前统计年度达标任务数 ÷ 有正目标任务数），无任务时仍 null。

## 二十七、五年累计进度口径（2026-10-25）

用户反馈：五年计划应以「五年总量目标」为 100%（如某学院五年出 5 本教材，不必每年 1 本，五年完成 5 本即可），年度目标只是过程刻度；此前各页面完成率几乎全是当年口径，看不到五年累计进度。拍板：

1. **年度考核机制保留**：年度核算仍判达标/未达标并生成待补做（PRD 核心规则不变），本次只优化运行期进度展示。

3. **接口加字段（均已补录 API 约定 15.8，纯新增不影响旧客户端）**：overview.cumulativeCompletionRate（可见 A 指标累计率平均）、tree 节点 cumulativeActual/cumulativeRate、by-unit/by-direction.cumulativeRate、trend.cumulativeActual/cumulativeRate、tasks 列表与详情 cumulativeActual/cumulativeRate。
4. **前端以五年累计为主进度**：P03 概览「五年总完成率」改用真累计口径（原为单年度计数制，名不副实）；P07 工作台任务卡片/表格主进度条改为五年累计进度（当年完成率降为辅助数值），KPI 加「五年累计完成率」卡；P05 详情头部改用后端累计字段（修正 GROWTH 口径原前端自算误取增长率的问题），B+ 明细表加累计进度列；P11 统计加累计 KPI 卡、维度表加累计列、单元排名图改累计口径；大屏仪表盘/完成进度条改累计口径，时间进度对比线改用规划期时间进度（新增 `timeProgressOfPlan` 工具函数，含单测）。

## 三十、滞后预警以实际完成率为前提（2026-10-27）

1. **无实际数据不判滞后**：`completionRate = null` 表示尚未形成审核通过的完成值，不再按 0% 参与滞后计算，避免新计划或未填报任务误报。
