## 1. 设计原则

| 原则 | 含义 | 落地要求 |
| --- | --- | --- |
| **简洁克制** | 后台工具以“办事”为主，界面不做装饰性设计 | 白底卡片 + 浅灰页面背景；一屏只有一个主按钮；避免多余的图标、渐变、插画（登录页和大屏除外） |
| **数据优先** | 用户来平台主要是看数字、填数字 | 关键数字用大号等宽数字；表格数字右对齐；完成率同时给“数字 + 进度条”；单位紧跟数值或放在表头 |
| **状态一目了然** | 指标、任务、填报、调整都有状态，用户需要一眼看出“到哪一步了、有没有问题” | 所有状态统一用 2.5 节的颜色映射；同一枚举在任何页面颜色一致；“有问题”的状态（未达标、驳回、滞后）必须用暖色并在列表中可筛选 |
| **层级清晰** | A → A+ → B 三级结构是业务核心 | 层级标签固定样式（2.5.9）；树形表格缩进 16px/级；编号始终显示在名称前面 |
| **操作留痕可见** | 调整、审核、解锁等操作必须“看得见历史” | 关键对象详情页都有“调整历史 / 审核记录 / 操作日志”入口；敏感操作必须填写原因；时间线展示“谁、何时、做了什么、意见是什么” |
| **守恒可校验** | 分解、调整必须满足守恒规则 | 前端实时计算合计和差值并高亮（体验层）；最终以服务端校验结果为准，错误逐项定位到单元格 |
| **权限即界面** | 不同角色看到的是“自己的平台” | 无权限的菜单不显示；无权限的按钮不渲染（而不是置灰）；因状态不允许的操作置灰并用 tooltip 说明原因 |
| **一致可复用** | 平台要支持多计划、多模板 | 页面不写死“五年”“11 个单元”；年度列、单元行均由数据驱动 |

### 2.5 状态颜色映射表

#### 2.5.1 通用映射原则

| 语义族 | 标签类型 | 适用状态 |
| --- | --- | --- |
| 未开始 / 无效 / 草稿 | `info` | 未激活、未开始、草稿、已撤回、待下发 |
| 进行中 / 流转中（正常） | `primary` | 进行中、执行中、待校领导审批 |
| 等待处理（需要人去处理） | `warning` | 待审核、待初审、已下发（待确认接收） |
| 调整相关 | `is-adjust`（紫） | 调整审批中、待接收方确认、已延期、已全部转出 |
| 完成 / 通过 | `success` | 已达标、已通过、已生效、已完成、已补做 |
| 问题 / 失败 | `danger` | 未达标、已驳回、逾期、待补做 |

- 状态标签统一 `size="small"`、`effect="light"`（默认）；需要“更醒目”时用 `effect="dark"`；“次要 / 已收尾”的状态用 `effect="plain"`。
- **属性标签**（层级、性质、口径）一律 `round` + `plain`，与状态标签在形状上区分，避免“约束性”被误读成“出错”。
- 前端遇到未知枚举值时：显示原值，用 `info` 样式，不报错（API 12 章要求）。
- 中文名称以 `GET /dicts/enums` 返回为准，下表为默认值。

## 3. 字体、字号与数值显示

### 3.1 字体族

不引用任何外链字体，全部使用系统字体：

```css
--app-font-family: "PingFang SC", "Microsoft YaHei", "Hiragino Sans GB", "Helvetica Neue", Helvetica, Arial, sans-serif;
--app-font-number: "DIN Alternate", "Bahnschrift", "Helvetica Neue", Arial, sans-serif; /* 大号 KPI 数字 */
--app-font-mono: Consolas, "SFMono-Regular", Menlo, monospace;                          /* requestId、JSON、编号 */
```

### 3.2 字号层级

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| H1 页面标题 | 20 / 28 | 600 | 页头标题（每页唯一） |
| H2 区块标题 | 16 / 24 | 600 | 卡片标题、弹窗标题、抽屉标题 |
| H3 小标题 | 14 / 22 | 600 | 表单分组、描述列表分组 |
| 正文 | 14 / 22 | 400 | 默认字号：表单、表格、按钮 |
| 辅助 | 12 / 20 | 400 | 表单提示、时间、表头注释、标签 |
| KPI 数字（大） | 32 / 40 | 600 | 概览页核心指标 |
| KPI 数字（中） | 24 / 32 | 600 | 指标卡、统计卡 |
| 大屏标题 | 36 / 48 | 600 | 大屏顶部标题（设计稿 1920 宽） |
| 大屏数字 | 40–56 | 600 | 大屏核心数字 |
| 移动端正文 / 辅助 / 标题 | 15 / 13 / 17 | 400 / 400 / 600 | 飞书 H5 |

- 表格密集场景（指标总表、日志）可用 `size="small"` 表格，正文 13px，但不得小于 12px。

### 3.3 数字字体

- 所有展示数字的位置（表格数值列、KPI、进度、金额、日期时间）必须设置 `font-variant-numeric: tabular-nums;`，保证数字等宽、上下对齐、实时变化时不抖动。
- 全局建议：`.el-table, .el-statistic, .num { font-variant-numeric: tabular-nums; }`。
- 大号 KPI 数字使用 `--app-font-number`，单位用正文字体、12–14px、次要文字色，与数字之间留 2px。

### 3.4 数值与百分比显示规则

API 约定：比率一律用小数传输（0.62 = 62%），前端只负责格式化，**不得自行汇总计算**（分解矩阵、调整预览的实时合计属于体验层计算，最终以服务端返回为准）。

| 数据类型 | 规则 | 示例 |
| --- | --- | --- |
| 计数类（项 / 个 / 人 / 门 / 张 / 人次） | 千分位，0 位小数 | `25,000` 人次、`5` 项 |
| 金额（万元） | 千分位，2 位小数 | `2,860.00` 万元 |
| 比值类（如生师比） | 1 位小数 | `18.0` |
| 百分比 / 占比 / 完成率 | ×100，**统一 1 位小数**，带 `%` | `0.62` → `62.0%`；`1.069` → `106.9%` |
| 增长率 | 1 位小数，正数带 `+`，负数带 `-` | `+2.8%`、`-1.5%` |
| 比率目标 | 按达成方向加前缀 | 越大越好 `≥ 65.0%`；越小越好 `≤ 18.0` |
| 是否型 | “是 / 否”；目标显示计划年份 | 目标 `是（2028 年）`；非计划年份显示 `—` |
| 增长率型五年目标 | 增长率 + 目标总量 | `+15.0%（3,289.00 万元）` |
| 差值 | 带符号；非 0 为红色，0 显示 `0 ✓` 绿色 | `-1`、`+1`、`0 ✓` |
| 空值 / null | 显示 `—`（U+2014），颜色 `#A8ABB2` | `—` |
| 分母为 0 / 无法计算 | 显示 `—`，hover 提示原因 | `—`（tooltip：分母为 0，无法计算） |
| 0 值 | 显示 `0`，不显示为空 | `0` |
| 大屏 ≥ 10 万的数字 | 以“万”为单位，1 位小数 | `12.3 万` |

- 完成率可以超过 100%，数字照实显示（如 `106.9%`），进度条最多填满 100%，并显示“超额”标签。
- 数值列一律**右对齐**；文本列左对齐；标签、操作、是否列居中。
- 计量单位统一时写在表头（`五年目标（项）`）；混合单位时单独一列“单位”。

### 3.5 日期时间显示

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 日期 | `YYYY-MM-DD` | `2026-12-31` |
| 列表中的日期时间 | `YYYY-MM-DD HH:mm` | `2026-10-20 15:32` |
| 日志 / 审计 | `YYYY-MM-DD HH:mm:ss` | `2026-10-22 09:14:07` |
| 消息、动态（24 小时内） | 相对时间，hover 显示绝对时间 | `3 分钟前`、`2 小时前` |
| 截止时间（剩余 ≤ 7 天） | 日期 + 剩余天数，橙色 | `2026-12-31（剩 5 天）` |

统一按 `+08:00` 展示，不显示时区后缀。

## 4. 间距、栅格、圆角、阴影

### 4.1 间距

以 **4px** 为基础单位：

| Token | 值 | 用途 |
| --- | --- | --- |

| `--space-6` | 24px | 页面大区块之间 |
| `--space-8` | 32px | 弹窗内边距（大）、空状态上下留白 |

### 4.2 栅格

- PC 使用 Element Plus 24 栅格（`el-row` / `el-col`），`gutter = 16`。

### 6.3 菜单与按钮的权限控制

## 7. 组件规范

### 7.1 表格（`el-table`）

**通用规则**

| 项目 | 规范 |
| --- | --- |
| 尺寸 | 默认 `size="default"`（行高 48px）；数据密集的指标总表、日志用 `size="small"` |
| 样式 | `border`（显示纵向分隔线，便于对照年度列）；`stripe` 不使用（与选中、hover 冲突）；表头背景 `#F5F7FA`、文字 `#909399`、600 |
| 对齐 | 数值右对齐、文本左对齐、标签 / 操作居中；编号列使用等宽字体 |
| 列宽 | 编号 110、层级 80、状态 100、负责人 90、日期时间 150、年度列 80；名称列 `min-width` 220 并 `show-overflow-tooltip` |
| 列固定 | 左侧固定“编号 + 名称”（`fixed="left"`），右侧固定“操作”（`fixed="right"`）；横向滚动时固定列出现 `--el-box-shadow-lighter` 分隔阴影 |
| 表头分组 | 年度目标用多级表头：`年度目标` → `2026 … 2030`；当前年度列表头加主色底线并显示“当前” |
| 操作列 | 最多显示 3 个文字按钮（`link` 类型），更多收进“更多 ▾”下拉；危险操作（删除）放在下拉最后、红色 |
| 分页 | `el-pagination` 右下角，`layout="total, sizes, prev, pager, next, jumper"`，默认每页 20 条 |
| 选择 | 需要批量操作时首列 `type="selection"`；选中后表格上方出现批量操作条“已选 n 项 [批量通过] [取消选择]” |
| 空数据 | 表格内使用 7.9 空状态（小号） |

**树形表格（指标总表 A → A+）**

- 使用 `row-key="id"` + `:tree-props="{ children: 'children' }"`；默认展开第一层（全部 A 展开显示 A+），工具栏提供“全部展开 / 全部收起”。
- A 行：白底、名称加粗、层级标签实心；A+ 行：背景 `#FAFBFD`，编号前缩进 16px，以“└”引导，层级标签浅色。
- 非量化 A（`isQuantifiable=false`）：没有展开箭头，名称后显示灰色小字“非量化 · 仅基础信息”，年度目标等量化列显示 `—`，不提供拆 A+ 或分解入口。
- 专业群的可量化 A：在主体名称前显示“群”字徽标；指标总表不展示 S 名称、S 归属或方向筛选。
- A 行的年度目标在“自动汇总”时 = A+ 之和，旁边显示 Σ 图标；“手工认定”时显示“认定”角标。

**合计行**

- 使用 `show-summary` + 自定义 `summary-method`，合计行背景 `#F5F7FA`、字重 600，固定在表格底部。
- 比率类列（占比、增长率、直填百分比）**不做简单求和**，合计行显示 `—` 或服务端返回的汇总值（Σ分子 ÷ Σ分母）。
- 分解矩阵的合计行之下，再显示“A+ 目标”和“差值”两行（见 10.1）。

### 7.7 文件在线预览抽屉

- **口径与输入项**（API 3.5 `MetricValue`）：

| 统计口径 | 输入项 | 实时计算展示 |
| --- | --- | --- |
| 增量累计型 `INCREMENT` | 本次新增数量 `amount`（整数） | 提交后累计值、预计年度完成率 |
| 存量时点型 `STOCK` | 当前总量 `total` | 较上年增量 `increment` |

| 数字 | 48px，`--app-font-number`，青色 `#3DD6F5`，tabular-nums；变化时 800ms 滚动动画 |
| 单位 / 标签 | 16px，`#8FA7D6` |
| 对比 | “时间进度 80.8%”用橙色；达成好于时间进度显示绿色 ▲，落后显示红色 ▼ |

### 9.3 图表类型选择

| 数据 | 图表 | 说明 |
| --- | --- | --- |
| 总完成率 | 环形进度（gauge / pie 环） | 中心显示百分比，外圈刻度 |
| 年度进度 vs 时间进度 | 双进度条 | 时间进度橙色，完成进度青色 |
| 约束性 / 发展性达标 | 数字 + 进度条 | 不用饼图（类别太少） |
| 执行单元排名 | 横向条形图（降序） | 按 `byUnit` 返回数量自适应一屏显示，不写死单元数；本单元（如有）高亮 |
| A 类指标完成情况 | 横向对比条 / 分组柱 | 使用 `byIndicator`，仅展示可量化 A；名称较长，横向更易读 |
| 年度趋势 | 柱（目标）+ 线（实际）+ 虚线（时间进度） | 未来年份柱体半透明，实际值为空 |
| 调整统计 | 数字块 | |
| 预警、动态 | 滚动列表 | 每 3 秒滚动一行，hover 暂停 |

大屏不展示 S；核心数字中的 A / A+ 仅统计可量化指标，当前预警和可执行 B 数量（含 `coreNumbers.taskCount`）排除历史任务，`byIndicator.taskCount / achievedCount` 仅统计当前非历史 B。历史已审核完成值仍按统计口径参与完成值汇总，比率为 `null` 时显示 `—`，不得按 0 绘制。

不使用：3D 图表、饼图展示超过 5 类的数据、雷达图展示完成率。

### 9.4 刷新与切换

- 数据刷新：默认 **60 秒**轮询一次 `GET /screens/{planId}?year=`（服务端缓存 1–5 分钟，因此前端轮询间隔不小于 60 秒）；右上角显示“数据更新于 21:03:15 · 58s”。
- 刷新时不出现 loading 遮罩，数字做滚动过渡，列表增量插入。
- 接口失败：保留上次数据，右上角显示红点“数据刷新失败，30 秒后重试”。
- 切换计划 / 年度：右上角下拉；选择“五年累计”时趋势图显示 5 年，选择单个年度时左侧显示该年度数据；切换后立即刷新并重置倒计时。
- 支持 URL 参数 `?planId=&year=&kiosk=1`（kiosk 模式隐藏返回按钮和下拉，用于会议室常驻）。

## 10. 交互细节

### 10.1 分解矩阵的实时合计校验

1. **实时计算**：任一非历史 B 单元格输入后（`input` 事件，防抖 150ms）重新计算：每行五年合计、每列合计、每列差值 = 合计 − A+ 年度目标；每列合计 = 历史冻结目标 + 非历史 B 目标，历史冻结目标只读且不可被清空或覆盖；五年合计列同样校验。
2. **高亮规则**：
   - 差值 ≠ 0 的年度列：表头文字红色并加 ⚠；该列所有单元格背景 `#FEF0F0`；合计单元格红字加粗；差值行显示 `+1` / `-1`（红色）。
   - 差值 = 0：差值行显示 `0 ✓`（绿色）。
   - 刚修改过的单元格：左上角 6px 主色三角，表示“未保存的修改”。
   - 有目标但未指定负责人的行：行首 3px 橙色竖条，负责人下拉红框，提示“请指定学院项目负责人（50002）”。
3. **顶部汇总提示**（`el-alert`）：
   - 平衡：`success`“各年度合计与 A+ 目标一致，可以下发”。
   - 不平衡：`error`“2028 年合计 9，比 A+ 目标少 1；2030 年合计 13，比 A+ 目标多 1”，点击年份可定位到该列。
4. **下发按钮**：不平衡或缺负责人时置灰，hover 显示原因清单；存在可编辑非历史 B 时**存草稿始终可用**（Q10），纯历史矩阵不提供存草稿、下发或其他写操作。
5. **服务端兜底**：保存后以 `PUT` 返回的 `summary` / `isBalanced` 覆盖前端计算结果；下发返回 `50001` 时，按 `errors[].field` 定位到单元格。
6. **比率类指标**：不显示“A+ 目标 / 差值”行，改为提示“占比型指标不做目标求和校验，A+ 完成值 = Σ分子 ÷ Σ分母”。
7. **并发**：保存返回 `10005` 时弹窗提示“该矩阵已被他人修改”，提供【查看最新】和【保留我的修改并覆盖】（后者重新获取 version 后再提交）。

### 10.2 调整申请的“调整前 / 后”对比

- 表格行 = 受影响的 B 任务（转出方、接收方；接收方没有该 A+ 的 B 时显示“新建”标签），每个任务两行“调整前 / 调整后”。
- 列 = 规划期各年度 + 五年合计。
- 变化的单元格：调整前值灰色删除线，调整后值加粗，减少为红色 `↓`、增加为绿色 `↑`，单元格背景 `#FDF6EC`。
- 表格底部守恒校验：
  - “A04-2 五年总量：50 → 50 ✓ 守恒”（转移 / 延期）；
  - “A04-2-C01 五年总量：9 → 9 ✓”（仅延期时，B 五年总量不变）；
  - 失败时红色显示规则和错误码（`70002`）。
- 发起时为**试算结果**（`/adjustments/preview`），标注“试算”；审批详情中为**快照**（`snapshot.before / after`），标注“快照 · 生效时间”。
- 冻结额度：提交后转出方单元格旁显示 `🔒 冻结 1`，审批结束后解除；迁移终止的在途申请保留终止原因、快照和审批轨迹，未生效冻结额度显示为已释放。
- 历史 B 不进入发起、试算或审批；历史调整记录只读。A+ 守恒试算必须保留历史冻结目标，转移只能由非历史 B 发起，接收单元须符合承接资格，自动新建的 B 也必须为非历史任务。

### 10.3 只读与锁定态

| 场景 | 触发条件 | 界面表现 |
| --- | --- | --- |
| 指标体系已定稿 | `finalize` 后 | P04 顶部 `el-alert info`“指标体系已于 2026-03-18 定稿（v3），修改目标需发起目标调整”；新增 / 导入 / 删除按钮不渲染；年度目标单元格只读；提供【发起目标调整】 |
| 已下发的分解矩阵 | 下发后 | P06 矩阵输入框变为纯文本；顶部提示“已下发，如需调整请发起延期 / 转移申请”+【发起调整】 |

| 无权限的指标 | 校级负责人查看他人指标 | 行内只有“详情”；详情页无编辑按钮，顶部小字“负责人：郑海燕，你只有查看权限” |

**只读样式**：输入控件改为纯文本展示（不是 `disabled` 灰框），保持可复制；锁定的表头 / 卡片标题前加 🔒 图标（`#909399`）。

### 10.4 其他交互约定

- **幂等与防重**：所有 ⚡ 接口在按钮点击时生成 `Idempotency-Key`；同一次操作重试使用同一个 Key。
- **乐观锁**：编辑类表单进入时记录 `version`，提交 `409 / 10005` 时提示刷新（7.11）。
- **跨页定位**：从待办、消息、飞书卡片跳转时，URL 带对象 ID（如 `/review?submissionId=`），页面自动选中并滚动到该对象，高亮 2 秒（主色浅底渐隐）。
- **筛选条件保持**：列表页的筛选、分页写入 URL query，刷新或返回时恢复。
- **键盘**：审核中心支持 `↑ / ↓` 切换上一条 / 下一条，`Ctrl + Enter` 通过（需二次确认）；分解矩阵支持 `Tab` / `Enter` 在单元格间移动。
- **代填 / 代审标识**：管理员代填 / 代审的记录，在列表和时间线中显示“代”字小标签和原因。
