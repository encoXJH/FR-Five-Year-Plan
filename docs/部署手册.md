# 部署手册

适用版本：阶段 8 及以后。本文档覆盖生产环境（Docker Compose 一体化部署）；开发环境见根目录 README.md。

## 1. 服务器要求

| 项目 | 最低配置 | 说明 |
| --- | --- | --- |
| CPU / 内存 | 2 核 / 4 GB | MySQL 约占 1 GB，后端 JVM 默认按容器内存 75% 自适应 |
| 磁盘 | 40 GB | 含 MySQL 数据、上传文件（`/app/data/files`）与备份 |
| 操作系统 | Linux（x86_64） | Windows Server 亦可，备份脚本需 Git Bash / WSL |
| 软件 | Docker 24+ 与 Docker Compose v2 | 无需预装 JDK / Node / Maven / MySQL |
| 网络 | 公网 HTTPS 域名 | 飞书网页应用、事件回调、OAuth 回调均要求公网 HTTPS；内网纯账号密码使用时可不配域名 |

## 2. 环境变量

复制 `.env.example` 为 `.env`，**必须修改**以下三项密钥（`openssl rand -hex 32` 生成）：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `DB_PASSWORD` | ✅ | — | MySQL root 密码（compose 中 mysql 与 backend 共用） |
| `JWT_SECRET` | ✅ | — | JWT 签名密钥，≥32 字节随机串 |
| `FILE_SIGN_SECRET` | ✅ | — | 文件签名地址 HMAC 密钥 |
| `DB_NAME` / `DB_USER` | | `metrics_db` / `root` | 数据库名 / 账号 |
| `JWT_ACCESS_EXPIRE_MINUTES` / `JWT_REFRESH_EXPIRE_DAYS` | | `120` / `7` | Token 有效期 |
| `FILE_STORAGE_DIR` | | 容器内 `/app/data/files` | 已挂载数据卷 `metrics-files`，一般不改 |
| `KKFILEVIEW_URL` | | 空 | OFFICE 在线预览服务；留空则前端提示下载 |
| `SWAGGER_ENABLED` | 生产 ✅ | compose 中 `false` | 接口文档开关；**生产必须 false**（API 约定第 14 章）。本地 `mvnw spring-boot:run` 默认 true |
| `CORS_ALLOWED_ORIGINS` | 生产 ✅ | 空 | 允许的来源，逗号分隔，如 `https://metrics.example.com`；前后端同域经 nginx 反代时无需配置 |
| `SCREEN_CACHE_SECONDS` | | `120` | 大屏聚合缓存秒数 |
| `RATE_LIMIT_*` | | 见 .env.example | 限流阈值（登录 10/IP/分钟等） |
| `REMINDER_ENABLED` / `REMINDER_CRON` | | `true` / 每天 08:30 | 截止提醒定时任务 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书必填 | 空 | 飞书自建应用凭证；**不配置则飞书集成整体不可用**（免登 20006、消息 SKIPPED、事件回调拒绝） |
| `FEISHU_REDIRECT_URI` | 飞书必填 | 空 | 浏览器 OAuth 回调，须与飞书后台「重定向 URL」完全一致 |
| `FEISHU_ENCRYPT_KEY` / `FEISHU_VERIFICATION_TOKEN` | 事件回调必填 | 空 | 飞书后台「事件与回调」页获取；不配置则事件回调一律 90002 拒绝 |
| `FEISHU_APP_BASE_URL` | 飞书必填 | 空 | 平台对外地址（如 `https://metrics.example.com`），用于消息卡片链接拼接 |
| `FEISHU_PUSH_ENABLED` / `FEISHU_PUSH_INTERVAL_MS` | | `true` / `60000` | 消息推送轮询开关与间隔 |
| `FRONTEND_PORT` | | `80` | compose 中前端对外端口 |

## 3. 飞书后台配置步骤

在 [飞书开放平台](https://open.feishu.cn/) 创建**企业自建应用**：

1. **凭证**：「凭证与基础信息」页取 App ID / App Secret → 写入 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`。
2. **权限（scope）**：
   - `contact:user.phone:readonly`（获取用户手机号——免登绑定与组织同步的匹配键）
   - `contact:contact:readonly_as_app` 或按界面勾选「获取通讯录基本信息 / 获取部门组织架构信息 / 获取用户基本信息」（组织同步用）
   - `im:message:send_as_bot`（以应用身份发消息——消息推送用）
   - 免登本身（code 换 user_access_token、获取用户信息）无需额外 scope，但用户信息含手机号依赖上面第一项
3. **网页应用**：「应用能力 → 网页应用」启用，桌面端 / 移动端主页填 `https://<域名>`（平台地址）。
4. **重定向 URL**：「安全设置」添加 `FEISHU_REDIRECT_URI`（如 `https://<域名>/feishu/callback`），与 `.env` 完全一致。
5. **事件订阅**：「事件与回调 → 回调配置」订阅方式选「使用回调地址」，请求地址填 `https://<域名>/api/v1/integrations/feishu/events`；保存时飞书发 `url_verification`，平台自动应答 challenge。保存后把 Encrypt Key / Verification Token 写入 `.env`。
6. **版本发布**：创建版本并提交发布，等学校管理员审核通过后生效。
7. **用户绑定**：用户在飞书内打开平台即自动按手机号绑定；也可先在「系统管理 → 用户」维护手机号，再由管理员触发 `POST /api/v1/integrations/feishu/sync-org` 批量预绑定。

> 不启用飞书时：以上全部留空，前端通过 `GET /api/v1/auth/feishu/config` 得到 `enabled=false` 自动隐藏入口；账号密码登录不受影响。

## 4. 启动步骤

```bash
# 1. 准备配置
cp .env.example .env && vi .env        # 填密钥与飞书配置

# 2. 构建并启动
docker compose -f docker-compose.prod.yml --env-file .env up -d --build

# 3. 验证
docker compose -f docker-compose.prod.yml ps            # 三个容器 up
curl http://127.0.0.1/api/v1/auth/feishu/config         # {"code":0,...,"enabled":...}
# 浏览器打开 https://<域名>，admin 登录（首次登录后立刻改密）
```

- 数据库由 Flyway 在后端启动时自动建表 / 迁移（V1–V5）并写入种子数据，无需手工执行 SQL。
- HTTPS 终止：参考 `deploy/nginx-https.conf.example` 在宿主机加一层 nginx（或学校统一网关），`server_name` 与证书路径需替换。

## 5. 备份与恢复

```bash
# 每日 02:00 备份（保留 14 天，BACKUP_KEEP_DAYS 可调）
chmod +x deploy/backup-mysql.sh
crontab -e
0 2 * * * DB_PASSWORD=$(grep ^DB_PASSWORD /opt/metrics/.env | cut -d= -f2) /opt/metrics/deploy/backup-mysql.sh >> /var/log/metrics-backup.log 2>&1
```

恢复：

```bash
gunzip -c /opt/metrics/backups/metrics_db-YYYYMMDD-HHMMSS.sql.gz \
  | docker exec -i metrics-mysql sh -c 'exec mysql -uroot -p"$DB_PASSWORD" metrics_db'
```

上传文件目录（数据卷 `metrics-files`）另行备份：`docker run --rm -v metrics-files:/data -v $PWD:/backup alpine tar czf /backup/files-$(date +%F).tgz -C /data .`。

## 6. 运维要点

- **升级**：`docker compose -f docker-compose.prod.yml up -d --build backend frontend`；Flyway 自动执行增量迁移。
- **日志**：`docker logs -f metrics-backend`；审计日志在库内（`GET /api/v1/audit-logs`）。
- **消息推送**：`notification.feishu_status` 终态为 SENT / FAILED / SKIPPED；FAILED 记录带 `feishu_last_error`。
- **事件回调**：处理结果在 `feishu_event` 表（RECEIVED → PROCESSED / FAILED）。
