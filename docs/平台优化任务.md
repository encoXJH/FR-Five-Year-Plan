# 平台优化任务提示词

> 来源：`docs/任务.txt`（2026-11-04 整理）。
> 使用方式：每个任务可独立交给开发执行；执行前必须阅读 `AGENTS.md`、`docs/五年计划指标管理平台-需求文档.md`、`docs/API统一约定文档.md`、`docs/界面设计规范.md`；每完成一个任务，更新 `docs/进度.md`，新增设计决策写入 `docs/开发决策记录.md`。

## 全局约束（所有任务必须遵守）

1. 不改变现有 S → A → B 业务层级与历史数据口径：历史 A+、旧 B 编号、旧执行历史保持只读兼容，禁止重写历史数据。
2. 新增或变更接口必须先补录 `docs/API统一约定文档.md`，统一 `/api/v1` 前缀、统一响应、字符串 ID、错误码；按 ID 访问的接口必须做服务端数据范围校验（越权 20005）。
3. 所有数值计算用后端 BigDecimal；写操作审计、敏感操作 reason、乐观锁 version、幂等键等既有规则不变。
4. 完成后必须通过：`./mvnw test`（后端）、`npm run build` 与 `npm run test`（前端），并在浏览器实测对应页面；前后端服务已在本地 8081 / 5173 运行，改动后重启验证。
5. 页面风格遵守 UI 规范（主色 #2B5BC0、状态标签映射、移动端学院工作台可用）。

## 任务 1：编号规则调整（指标按建设方向编码 + 学院数字编号）

**需求原文**：修改指标编码逻辑，以其所属建设方向的字母 A、B、C… 做开头，例如方向 A 下为 A01、方向 B 下为 B01；方向超出 26 个后使用 AA、BB… 等顺序。主要建设方向名称前不显示字母编号。学院编码统一以数字 01、02、03… 命名。

**现状**：
- 建设方向已有计划内字母编号 `direction.code`，但页面错误地将方向展示为 `A · 方向名称`。
- A 指标编号仍由 `IndicatorRules.nextACode()` 按计划统一生成 A01、A02…，未与所属建设方向联动。
- 执行单元当前编码为 C01–C10、S01；B 任务编号为 `{指标编号}-{单元编码}`。

**改造要求**：
1. 建设方向保留计划内字母编码 A、B、C…Z，第 27 个起为 AA、BB、CC…；编码只作为指标编号前缀，不在主要建设方向名称、下拉选项或其他方向展示位置显示 `A ·` 等前缀。
2. A 指标编码改为 `{所属方向字母编码}{两位序号}`：方向 A 下为 A01、A02…，方向 B 下为 B01、B02…，方向 AA 下为 AA01、AA02…；各方向独立取号，计划内编码唯一。存量指标通过 Flyway 按所属方向和原排序批量重编，ID、目标、填报、审核和执行关联不变。
3. 未分配建设方向的指标暂按计划内 A 系列取号，分配方向后自动换成对应方向编码；已下发或历史数据不允许通过页面随意改编码。
4. 学院（执行单元）编码统一迁移为纯数字 01、02、03…，新增单元继续自动取最大数字序号 +1；新 B 任务编号同步为 `{新指标编码}-{数字单元编码}`，如 `B01-03`。存量新 A→B 任务通过 Flyway 按当前指标与单元编码统一重编；历史 A+ 下的旧 B 编号、快照、审计与执行记录保持不变。
5. 必须通过 Flyway 完成存量指标与执行单元编码迁移，不允许手工 UPDATE 生产数据代替迁移；迁移不得改变业务 ID 和历史任务关联。

**涉及文件**：`module/indicator/service/support/IndicatorRules.java`、`IndicatorService.java`、`IndicatorExcelService.java`、`PlanService.java`、执行单元相关实体/服务（system 模块）、`frontend/src/views/indicators/index.vue` 及其他方向展示页面。

**验收标准**：方向 A/B 下的指标编码分别从 A01/B01 开始，第 27 个方向下从 AA01 开始；方向名称只显示名称本身；现有和新增学院编码均为 01、02…；新任务编码采用新规则，历史任务与执行数据仍可读取；后端编码生成和迁移边界有单元测试。

## 任务 2：指标总表——建设方向侧栏收起/展开 + 快速筛选

**需求原文**：在指标总表中将主要建设方向做一个收起和展开侧边的功能；在关键产出指标的左边新增可以选择的下拉框选择主要建设方向进行快速筛选。

**现状**：`frontend/src/views/indicators/index.vue` 已展示建设方向与关键产出指标总表，材料列为独立列，支持按计划加载。

**改造要求**：
1. 建设方向区域改为可收起/展开的侧边栏，记住用户收起状态（localStorage），展开/收起有过渡动画，收起后指标表格占满宽度。
2. 在"关键产出指标"列/区域左侧新增建设方向下拉筛选框：选项含"全部方向"及各方向名称（不显示字母前缀），选择后立即过滤表格，仅前端筛选不重复请求全量数据；与已有的计划切换、材料数量、自动刷新逻辑兼容，切换计划时清空旧筛选。
3. 筛选状态同步到 URL query，刷新后保留。

**验收标准**：桌面与窄屏下侧栏收起/展开正常；筛选后表格行数、材料数量、进度展示正确；快速切换方向不出现旧请求覆盖（沿用请求代次校验）。

## 任务 3：材料库多选与一键导出 ZIP

**需求原文**：材料库增加多选功能，可以勾选文件进行一键导出为 zip 压缩包。

**现状**：`frontend/src/views/materials/index.vue` 已支持计划隔离、指标/任务筛选、单文件预览下载；材料仅展示审核通过的填报材料，直接上传权限仅 ADMIN / SCHOOL_OWNER。后端在 `module/file`（MaterialService、StorageService）。

**改造要求**：
1. 列表增加复选框（含表头全选当前页/跨页选择说明），选中后顶部出现"导出 ZIP（N）"按钮；仅可选择当前用户数据范围内、审核通过的材料。
2. 导出优先后端同步生成 ZIP（文件清单 + 原始文件名，重名自动加序号），通过既有下载/审计通道返回；文件较多时复用异步导出任务机制，避免接口超时。
3. ZIP 内按"建设方向/指标编号/材料名"或"指标编号_材料名"组织目录，附 manifest（材料名、指标、任务、学院、审核通过时间）。
4. 服务端逐个校验选中材料的数据范围与状态，越权 20005；下载写审计日志；前端处理空选择、部分文件已删除的失败提示。

**验收标准**：勾选 3 个文件导出 ZIP 可解压且文件名/目录正确；学院角色只能导出本单元材料；大文件导出无超时；审计有记录。

## 任务 4：统计报表下发学院查看 + 学院工作台按指标总表风格改造

**需求原文**：统计报表可以下发学院让学院查看，开通查看接口；将学院工作台的风格改为指标总表的风格，能更快速看到哪些材料没有上传提交完成，进行更快的预览。

**改造要求**：
1. **报表查看**：统计报表对所有拥有 `stats:view` 的角色开放，学院负责人直接查看本单元数据（服务端按 UNIT_OWNER 数据范围过滤，禁止看到其他学院明细）；不设报表下发步骤，不保留“下发报表”按钮、下发配置接口与 `stats:distribute` 权限。查看接口需补录 API 文档、鉴权与数据范围测试。
2. **工作台改造**：`frontend/src/views/workbench/index.vue` 的整体版式与指标总表一致：页标题区 + 左侧可收起状态侧栏 + 主区筛选条 + 汇总条 + 扁平表格 + 底部统计，保留现有 KPI（待填报、待审核、本年完成率）与填报/审核操作，材料列“共 N 份”可点击预览。
3. **材料缺口预览**：按任务/指标直观标识"材料未上传 / 未提交 / 审核中 / 已通过"状态；缺材料任务可一键展开材料清单或直接打开上传/预览对话框；未产生完成值的任务完成率仍按 0 计入平均分母（既有修复不得回退）。
4. 移动端至少保证填报、待办、材料预览可操作。

**验收标准**：下发前后学院账号可见范围正确（越权请求返回 20005）；工作台可直接定位缺材料任务并预览；现有 255+ 前端测试及新增测试通过。

## 任务 5：统计报表——删除统计维度、修复年度与五年累计统计

**需求原文**：统计报表进行修改，统计维度进行删除；修年度、五年累计无法正常统计的 bug。

**改造要求**：
1. 移除统计报表页（`frontend/src/views/stats/index.vue` 及后端 stats 模块对应参数）中的"统计维度"切换/分组维度，保留计划 + 年度（或五年累计）主口径；删除后端不再使用的维度参数与分支，不做兼容残留。
2. 复现并修复年度统计与五年累计统计异常：重点核查 GROWTH（actualTotal 口径）、RATIO（Σ分子÷Σ分母）、LOWER_BETTER 达成方向、null 完成值按 0 计入、计划卡片与统计概览口径一致性等既有修复点是否在此页面缺失。
3. 修复必须带后端单元测试：构造年度/五年累计的边界数据（无填报、部分学院填报、跨年度、比率类）验证结果。

**验收标准**：页面不再出现统计维度入口；同一计划同一年度下，统计报表、统计概览、计划卡片数值一致；五年累计与逐年度明细对得上；`./mvnw test` 通过。

## 任务 6：调整申请与审批——任务勾选与计划切换优化

**需求原文**：调整申请与审批进行优化，学院任务可以更直观勾选选择需要调整的；需要显示这是哪个学院的任务、哪一个建设方向、哪一个指标等和编号；别的计划需要怎么切换，更直观看到。

**现状**：`frontend/src/views/adjustment/index.vue` + 后端 `module/adjustment`；调整规则（类型适用范围、审批链、额度冻结、守恒校验）已稳定，不得改变业务规则。

**改造要求**：
1. 发起调整时，任务选择改为表格勾选（单选/多选按调整类型限制），每行清晰展示：学院（执行单元编号+名称）、建设方向名称（不显示字母前缀）、指标编号与名称、任务编号、当前年度目标与剩余可调整量。
2. 顶部提供明显的计划切换器（计划名称 + 状态 + 起止年份），切换计划时清空已选任务与旧缓存并重新加载，沿用请求代次校验防止旧响应覆盖。
3. 勾选后即时显示可调整类型提示（INCREMENT 可延期/转移、BOOLEAN 仅延期、其他仅目标调整），不合法选择在提交前即提示，仍保留服务端 70006 校验。
4. 审批详情页同步展示上述任务归属信息，便于审批人识别。

**验收标准**：跨计划切换无串数据；勾选任务后试算/提交信息完整；审批人能看到学院、方向、指标、编号；既有调整审批测试全部通过。

1. 字母编号超出 Z 后为 AA、BB、CC…（按需求原文），非 Excel 的 AB、AC。
2. 现有与新增执行单元统一使用纯数字编码；仅既有任务的历史编号、快照、审计与执行记录保留原值，不批量重写。
3. 报表下发粒度 = 计划 × 执行单元；下发后学院仅见本单元汇总与明细。
4. ZIP 导出默认同步生成，超过 50 个文件或 200MB 时转异步导出任务。
