## 1. [P1] 同一 A 下不同 B 并发审核仍可能丢失 A 汇总值

位置：`backend/src/main/java/edu/fzrj/metrics/module/submission/service/ActualRecalcService.java` 的 `recalcAIndicatorYear`、`taskYearResults`、`upsertIndicatorCache`。

目前任务年度锁仅保证同一 B 的审核串行。A 汇总先执行普通 SELECT 读取所有 B 的完成值并算出结果，随后才对 A 的年度缓存加 FOR UPDATE 锁。两个学院的 B 可各自持有任务年度锁并先完成来源读取：事务一只看到自己的新值，事务二也只看到自己的新值。事务二等待 A 锁后虽然读到了最新缓存行/版本，却仍使用加锁前已经计算好的汇总值覆盖它。乐观锁此时不会阻止覆盖，因为版本来自最新锁定行。

STOCK/GROWTH 的汇总及历史 A+ 上卷路径也需一起核对，不能仅修复纯 A→B 的增量分支。

验证：通过模拟交错，来源读取只有 2，而随后锁到的 A 当前值已为 9，方法仍将 A 写成 2。真实 MySQL 的“同一 A、两个不同 B”并发场景尚未运行；现有同一 B 的并发测试不能证明该场景安全。

建议：在统一锁序下先锁聚合节点，再使用最新来源计算；跨任务/指标聚合要统一一致性读与锁定读策略，并补两个不同 B 同时审核的数据库回归。

## 2. [P1] 全局文件去重与新绑定鉴权冲突

位置：`backend/src/main/java/edu/fzrj/metrics/module/file/service/FileService.java` 的 `initMultipart`、`store`、`findBySha256`、`requireBindable`。

上传仍按全库 SHA-256 直接返回原有 file_info，不区分上传者。新鉴权却只允许原上传者、管理员或原业务既有引用绑定该文件。用户 B 正常上传了与用户 A 内容相同的文件后，得到 A 的文件 ID，随后创建自己的填报/关联指标时必然被拒绝 20005。常见的同版模板、公共证明材料会触发此问题。

验证：全局去重返回文件 77（上传者 88），当前用户 99 用它建立新业务引用，绑定接口返回 20005。

建议：区分物理内容去重与业务文件归属，复用存储对象时为新上传者创建独立的文件元数据；或者将当前去重暂时限制在同一上传者范围。不能通过放松绑定权限来修复，否则会重新引入之前的附件越权漏洞。

## 3. [P1] 自动刷新会覆盖请求发出期间产生的编辑

位置：`frontend/src/utils/autoRefresh.ts` 的 `run`，以及 `frontend/src/views/system/components/SettingsPanel.vue` 的 `load`、填报页的 `reload`、审核页的 `loadDetail`。

skip/dirty 只在发出刷新请求之前检查。网络请求等待期间，界面保持可编辑；用户开始输入后，响应仍直接覆盖表单、清空 edits，或调用 populate/initReviewForm。用户编辑后才打开弹窗，也不能取消之前发出的刷新。因此“存在未保存编辑就暂停”的入口判断不能保证数据不被覆盖。

验证：使用 SettingsPanel 中实际的 load 函数体与可控 Promise，先发出 load(true)，再写入 `plan.fillDeadline=11-30`，最后返回刷新响应，edits 被清成 `{}`。

建议：响应落地前重新核对编辑状态、选中对象与请求代次；若期间发生编辑，丢弃该响应对表单的写回。测试应覆盖“请求中开始编辑”，而不只测试发请求时 dirty=true。

## 4. [P2] 新审计切面破坏已有返回值型 before 表达式

位置：`backend/src/main/java/edu/fzrj/metrics/common/audit/AuditLogAspect.java` 的 `doAround`，`SettingController.patch` 与 `UserController.updateRoles` 的审计注解。

切面现在在调用业务方法之前求值 before；但这两个入口仍声明 `before="#result.auditBefore"`。此时尚未设置 result，表达式求值抛 EL1007E，异常被捕获后继续写入 `before_json=null`；after 正常，因此角色/参数变更的旧值审计反而回退丢失。

验证：用 SettingController 的实际注解调用切面，复现 EL1007E，最终日志为 `beforeJson=null, afterJson={"k":"new"}`。

建议：兼容从返回对象提供的审计前值，或将两个入口改为真正的调用前快照读取表达式，并为两种 before 来源分别补切面测试。
