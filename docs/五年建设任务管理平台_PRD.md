## 背景与产品目标

从表格分工转为可执行、可审核、可追责的任务闭环。

### 1.1 背景与问题

五年建设目标涉及学校、专业群、学院和校级协同部门。现有清单能够描述目标，但年度拆解、学院执行、材料审核和指标调整仍需要统一的产品规则。若仅靠表格流转，容易出现目标口径不一致、审核进度不可见、调整后责任不清和历史记录缺失。

**表格中的建设目标 缺少统一执行口径 → 校级量化并拆解学院任务→ 学院以佐证材料 证明完成结果 → 校级人工认定 同步年度里程碑 → 甘特图呈现 调整全程留痕**

### 1.2 产品目标

#### 目标可执行

将主要建设方向量化为关键产出指标，再分解为学院任务并设置年度里程碑。

#### 结果可认定

学院提交完成值与在线可预览的佐证，校级人工审核后形成年度达成结论。

#### 过程可追溯

保留原目标、调整目标、审核版本、确认记录和操作日志，支持按时间导出。

### 1.3 可观察的完成结果

- 校级负责人能把同一关键产出指标配置到 2026—2030 年，并下发至一个或多个学院。
- 学院负责人只处理本学院任务，可保存草稿、上传材料、提交审核和在退回后修订重报。
- 审核结论自动更新里程碑与甘特图；未审核的填报不计入认定完成值。
- 年度顺延、跨学院划转和后续年度补位均不覆盖原始记录。

## 业务对象与核心流程

统一定义对象，避免把建设方向、量化指标和学院执行任务混为一谈。

### 4.1 指标层级与对象关系

**目录级：大模块／建设目录 → 计划级：五年建设计划 → 方向级：主要建设方向 → 指标级：关键产出指标 → 任务级：学院任务 → 年度级：里程碑与填报**

| 对象 | 产品定义 | 关键规则 |
| --- | --- | --- |
| 建设目录 | 承载一套或多套建设计划的大模块。 | 可设置 1 名校领导为总负责人；目录不是指标，不参与数值汇总。 |
| 建设计划 | 具有名称、建设范围、起止年度和校级负责人的任务集合。 | 首个计划周期为 2026—2030；模板化计划可设置其他周期。 |
| 主要建设方向| 专家下发的原始主要建设方向。 | 对应源表“建设任务/主要建设方向”，仅表达方向，不直接填报。 |
| 关键产出指标| 经校方量化后的关键产出指标。 | 对应“关键产出指标”；配置类型、单位、五年目标和多年度目标，是下发与核算的统一口径。 |
| 学院任务 | 校级给各学院下发的执行任务，由关键产出指标分解形成。 | 继承关键产出指标类型、单位和核算方式；一项关键产出指标可生成多项学院任务，校级直管指标可不生成学院任务。 |
| 年度里程碑 | 学院任务在某个建设年度应达成的目标及认定状态。 | 以年度目标是否达成为单位；审核认定后更新，不用上传动作直接代替完成。 |
| 填报与佐证 | 学院对某里程碑的完成说明、完成值和证据版本。 | 每次提交形成独立版本；退回不覆盖旧版本。 |
| 调整单 | 年度顺延或跨学院划转的业务记录。 | 保存调整前后快照、原因、确认和审批过程。 |

### 4.2 P0 主流程

**校级建立计划 导入／选择主要建设方向与关键产出指标→ 配置五年与年度目标 分解并下发学院任务→ 学院接收任务 填报并上传佐证 → 校级在线预览 人工审核认定 → 里程碑更新 甘特图同步**

恢复路径：填报被退回后，学院保留原填写内容，依据审核意见修订并生成新版本重新提交；未达标里程碑可进入顺延或后续补位流程，涉及其他学院时转入跨院划转流程。

## 功能需求

每项需求均说明触发、处理、结果、状态和异常，是设计与管理端开发的主要依据。

### FR-01 建设目录、计划与模板复用（P0）

目的：用统一的流程骨架承载不同专业群或不同批次建设任务，降低重复配置成本。

#### 触发与处理

1. 校级负责人选择建设目录，新建空白计划或从已有计划复制；新建时填写名称、建设范围、起止年度和项目负责人。
2. 从已有计划复制时，平台复制目录结构、主要建设方向、关键产出指标和学院任务层级、指标核算配置、责任角色和流程规则。
3. 复制后生成独立计划。后续修改新计划，不反向影响源计划。
4. 用户可选择“仅复制结构”或“复制结构及目标值”。无论选择哪种方式，均不得复制完成值、佐证、审核结论、待办、调整单和历史日志。

#### 结果与边界

- 新计划初始状态为“草稿”；只有必填量化与校验完成后才能发布。
- 计划发布后周期不可直接修改；如确需变更，须通过新版本计划处理 TBD。
- 复制存在未完成校验的源指标时，允许复制但保留“待完善”标记，不允许直接下发。

### FR-02 指标库、Excel 导入与结构化校验（P0）

目的：把首批清单转为可管理的数据，同时保留源文以便追溯，不把自由文本误当成最终任务。

#### 源字段映射

| 源字段 | 平台业务字段 | 导入处理规则 |
| --- | --- | --- |
| 序号 | 来源序号 | 仅作溯源与排序，不作为跨计划唯一标识。 |
| 建设任务/主要建设方向| 主要建设方向名称 | 同名方向合并关联，保留来源序号顺序。 |
| 关键产出指标| 关键产出指标名称与原始描述 | 完整保留，不截断括号内的统计口径。 |
| 指标类型 | 指标类型字典 | 仅接受约束性、发展性、特色；其他值进入异常清单。 |
| 指标单位 | 单位原文与标准单位 | 保留“门/个”“个或人”等复合单位；标准化需人工选择，不擅自拆项。 |
| 专业群5年量化目标 | 关键产出指标专业群五年目标原文／解析值 | 空值、0、“—”分别表示未提供、数值零、不适用，三者不得混淆。 |
| 专业群2026年量化目标 | 关键产出指标2026 目标原文／解析值 | 写入 2026 年里程碑待确认值。 |
| 专业群五年指标分配 | 学院任务五年分配参考原文 | 提取学院、括号数值和备注，形成待确认分解，不直接发布。 |
| 专业群2026年指标分配 | 学院任务2026 分配参考原文 | 同上；“无”仅表示该字段未分配，不自动等于数值 0。 |
| 学校5年量化目标 | 学校整体五年目标原文／解析值 | 与专业群目标分字段保存，不相互覆盖，不自动加总。 |
| 学校2026年量化目标 | 学校整体 2026 目标原文／解析值 | 保留“专业群为 X、余 Y”等结构说明。 |
| 学校2026年任务分工 | 2026 校级分工原文 | 识别牵头部门、学院及年度说明；不自动将牵头部门变成学院。 |
| 学校2027—2030年任务分工 | 对应年度分工原文 | 分别进入对应年度；空白保持空白，由校级后续量化。 |

#### 导入流程

1. 校级负责人上传清单并选择目标计划；系统先显示工作表、字段和指标数量预览，不直接写入正式计划。
2. 系统执行必填、字典、学院名称、数值格式、年度、目标与分配一致性检查，输出“可导入、需确认、不可导入”三类结果。
3. 用户逐项处理异常；可导入项与已确认项进入计划草稿，源文件与源行号随记录保存。
4. 同一源文件重复导入时，按“计划 + 来源文件 + 来源序号”提示重复，由用户选择跳过或重新生成草稿，禁止静默重复。

#### 校验与异常

- 数值型单位的目标须为可解析数值；百分比可配置为 15 或 15% 的输入显示，但内部业务口径必须统一为百分比值。
- “是/否”只接受是、否或空白；“比值”保留比例表达式并要求配置可核算口径。
- 学院别名无法映射到标准名录时，不生成学院任务，进入人工匹配。
- 目标与括号分配值不一致时标记“分配待确认”，不阻止保留关键产出指标草稿，但阻止下发相关学院任务。
- 对“省厅统计、学校无需填写”等指标，允许标记为“外部数据／免填报”，数据来源与更新责任 TBD。

### FR-03 主要建设方向与关键产出指标量化及多年度里程碑配置（P0）

目的：由校方老师自行设置各年度指标，不由开发侧预设具体数值。

#### 配置规则

1. 主要建设方向仅需维护方向名称、排序、说明和目录归属；关键产出指标继承主要建设方向并补充完整量化定义。
2. 关键产出指标编辑区同时展示五年总目标和 2026—2030 五个年度字段。首年可从源表带入，其他年度允许逐年编辑。
3. 校级负责人须选择核算方式：累计型、年度定额型、期末型、比率型、增长率型、是否型或外部数据型。不同方式的目标校验、进度和补位规则统一引用第 6 章。
4. 百分比或比率指标必须填写基期、分子来源、分母来源、目标方向和统计口径；增长率指标须先填写可核算的基期绝对值与年度绝对值。
5. 约束性、发展性、特色是指标管理属性，不直接决定公式；同一类型可使用不同核算方式。

#### 发布与变更

- 关键产出指标保存草稿时不要求五年全部年度一次性填满，但发布学院任务时，被发布年度必须有合法目标或明确“不设置年度目标”的期末型规则。
- 已下发关键产出指标的类型、单位、核算方式及已执行年度目标不可直接覆盖；须通过调整流程生成变更记录。
- 未来未开始年度允许校级修改目标，但若已有关联填报、待确认调整或审核记录，则冻结并提示先处理关联业务。
- 空值表示未量化；0 表示目标值为零；“—”表示不适用。发布前必须显式确认。

**源表示例对应**

“专业群每年系统绘制不少于 2 门专业核心课程能力图谱”为约束性、单位“门”、五年 10 门、2026 年 2 门，适合累计型；“订单式人才培养比例”适合比率型／每年达标，不应把五年百分比按年度相加。

### FR-04 关键产出指标分解与学院任务下发（P0）

触发：关键产出指标量化达到发布条件，校级负责人在指标详情中选择“分解至学院”。

#### 处理规则

1. 选择一个或多个学院，为每个学院创建独立的学院任务；学院任务默认继承关键产出指标描述、指标类型、单位和核算方式。
2. 按年度填写各学院目标、学院负责人和执行说明。可引用源表分配原文，但最终值以校级确认的结构化字段为准。
3. 累计型、年度定额型等可分解数量指标须校验学院任务目标合计与关键产出指标分配口径；比率型、是否型允许“共同承担”，不得强行相加。
4. 若源表仅表达候选学院或牵头关系，校级可标记“非加总分配”，并填写原因；该原因随下发记录保存。
5. 下发前显示关键产出指标总目标、已分配、未分配、各学院年度目标和差异。存在未解释差异、负责人缺失或目标非法时阻止下发。
6. 确认下发后，学院任务状态为“待接收”，学院产生待办；关键产出指标和学院任务均保存下发快照。

#### 撤销与冲突

- 学院接收前，校级可撤销下发并填写原因；撤销后任务回到草稿，保留日志。
- 学院已接收或已有填报后不可直接撤销，只能通过调整或终止流程处理；终止规则 TBD。
- 同一关键产出指标可向同学院分解多项学院任务时，必须填写不同执行范围，防止重复计算。

> **流程示意：**下发校验：填写学院年度目标 → 校验合计、负责人和差异 → 校验通过后下发 → 学院任务进入“待接收”。

### FR-05 学院任务接收、填报与佐证管理（P0）

触发：学院负责人收到本学院任务待办。

#### 接收与填报

1. 学院查看关键产出指标目标摘要、本学院任务目标、年度里程碑、统计口径和校级说明后执行“接收任务”；学院任务进入“执行中”。
2. 对任务口径有异议时，学院可提交异议说明，不直接修改目标；校级处理前可继续查看但不能下发新的调整 TBD。
3. 在年度里程碑中填写完成值、完成说明、成果名称、完成日期和佐证材料；支持保存草稿并稍后继续。
4. 提交前校验必填项、数值范围、完成日期、材料数量与在线可预览性。至少上传 1 项有效佐证；外部数据型按单独规则处理。
5. 提交后生成不可变填报版本，里程碑进入“审核中”，原填写内容不可直接编辑。

#### 佐证材料

- 支持文档、图片、PDF、视频；常见文档具体扩展名、单文件大小、单次数量及视频时长上限 TBD。
- 每份材料记录文件名、格式、上传人、上传时间、说明和所属填报版本。
- 上传失败不得丢失已保存的文本草稿；可单独重试材料。材料未具备预览条件时不能提交。
- 审核中不可删除该版本材料；退回后修订须生成新版本，旧材料仍可追溯。

### FR-06 校级人工审核与年度认定（P0）

触发：学院提交年度填报，进入校级负责人的审核待办。

#### 审核界面与动作

1. 同屏展示关键产出指标统计口径、学院任务年度目标、学院填报值、历史版本、完成说明和佐证材料。
2. 文档、图片、PDF、视频须在平台内直接预览；审核人员无需下载即可完成审核。
3. 校级负责人选择“通过”或“退回”，填写审核意见。退回必须说明需修订的具体内容。
4. 通过时可填写“认定完成值”。认定值与学院填报值不同，必须填写认定依据；学院原始填报值保持不变。
5. 审核提交需二次确认，结论记录审核人、时间、意见和材料版本。

#### 结果与状态

- “通过”表示完成值与材料被人工认定，不表示所有类型都必然达标。系统按年度规则比较认定值与目标：达标则里程碑“已完成”，未达标则“已认定未达标”。
- “退回”后里程碑进入“已退回”，学院可修订重报；已退回版本只读。
- 审核中的填报可由学院撤回，前提是尚未形成审核结论；撤回到草稿并记录原因。
- 已审核结论若需纠错，不直接编辑，须发起审核更正流程；更正审批权限 TBD。

> **流程示意：**填报审核：学院草稿 → 提交审核 → 校级在线预览并人工审核 → 按认定值判定“已完成”或“已认定未达标”；退回后生成新版本重报。

### FR-07 分层甘特图与年度里程碑视图（P0）

目的：将原“查看详细数据”主入口改为“甘特图”，用时间、层级和状态表达执行情况。

#### 布局与交互

1. 左侧为主要建设方向→ 关键产出指标→ 学院任务可展开树，右侧为计划年度时间轴；首个计划显示 2026—2030 五列。
2. 主要建设方向与关键产出指标行用于聚合查看，学院任务行展示年度执行条或里程碑节点；是否型和期末型以节点呈现，累计型可显示跨年度条。
3. 每个年度单元显示目标值、认定值和状态。状态除颜色外必须有文字或图形标识，避免仅凭颜色判断。
4. 点击节点打开侧栏，显示目标、认定完成值、差额、审核状态、最近填报、调整标记及佐证入口。
5. 支持按计划、主要建设方向、学院、负责人、指标类型、年度和里程碑状态筛选；筛选结果与当前用户数据权限一致。
6. 未下发、未填报、审核中、已完成、已认定未达标、已退回和已调整采用不同样式；发生顺延或补位时显示关联年度。

#### 空态与汇总

- 无任务时显示当前筛选条件和“清除筛选”，不展示伪造的空进度条。
- 主要建设方向与关键产出指标聚合以里程碑状态数量呈现，不对不同单位、不同核算方式的百分比做简单平均。
- 当前年度之后的目标可展示但不计入逾期的当前执行统计；逾期判定需结合计划年度截止日期，具体日期 TBD。

> **流程示意：**甘特图：左侧展示主要建设方向—关键产出指标—学院任务树，右侧展示 2026—2030 年时间轴；点击节点查看目标、认定值、差额、审核与调整记录。

### FR-08 年度指标顺延与后续超额补位（P0）

适用：同一学院任务内的累计型指标。年度定额型、比率型等是否允许特殊顺延，须由校级另行配置并说明，不默认抵扣。

#### 年度顺延

1. 年度认定后存在缺口，或校级确认当年无法完成时，可发起顺延。
2. 顺延量不得超过该年度未弥补缺口；接收年度必须是同一计划内尚未结束的下一年度或以后年度。
3. 保存原年度目标、原认定值、顺延量、接收年度、原因和发起人。原年度记录保留“已顺延”关联标记，不改写历史。
4. 生效后，接收年度目标 = 原接收年度目标 + 本年顺延量 + 其他已生效顺延；五年总目标保持不变。
5. 同一年度存在审核中填报或待审批调整时，不允许重复顺延同一缺口。

#### 后续年度补位

- 后续年度认定值超过当年调整后目标时产生可补位余量。
- 系统按年度先后，将余量优先用于同一学院任务内最早未弥补缺口；保留缺口年度与补位年度的双向关联。
- 补位只改变缺口的“已弥补量”，不修改任一年度原目标和原认定值。
- 五年认定完成值使用实际认定总量核算，不能把同一余量同时计入两个年度的总完成量。

Assumption, TBD 年度顺延由校级项目负责人审批后生效，校领导可查；若需校领导审批，应在实施前调整权限矩阵。

### FR-09 跨学院指标划转与三方审批（P0）

目的：将无法由原学院完成的指标调配到其他学院，同时明确双方责任和校领导最终审批。

#### 发起条件

- 仅允许同一关键产出指标下、单位与核算方式一致的学院任务之间划转；必须指定五年总目标或具体年度目标。
- 可划转量 ≤ 原学院目标剩余可调整量。已认定完成量、审核中填报占用量和进行中调整占用量不得重复划转。
- 发起人填写原因、转出学院、转入学院、划转量、影响年度和说明材料；转出与转入双方均看到同一调整单。

#### 审批顺序

**校级负责人 发起划转 → 转出学院 确认或退回 → 转入学院 确认或退回 → 校领导 最终审批 → 双方目标生效 快照与日志留存**

1. 任一方退回时必须填写意见，调整单终止，不改变目标；校级可复制原单修订后重新发起。
2. 校领导审批前，发起人可撤回，撤回后释放占用量并留痕。
3. 校领导批准后，转出任务扣减目标，转入任务增加既有目标或生成新的学院任务；关键产出指标总目标不变。
4. 系统同时保存原指标记录、调整后指标记录、双方确认、审批意见、时间和完整前后快照。
5. 生效后甘特图显示“跨院划转”标记，双方学院只看到与自身相关的执行明细，校级与校领导可查看完整链路。

> **流程示意：**跨院划转：校级发起 → 转出学院确认 → 转入学院确认 → 校领导审批 → 调整后目标生效并保留前后快照。

### FR-10 进度核算与双维度结算（P0）

触发：审核通过、审核更正生效、年度顺延生效或跨院划转生效。

1. 平台只将已审核认定值纳入正式完成量；草稿、审核中和已退回版本单独显示，不计入。
2. 每次核算保存目标版本、认定值、公式口径和计算时间；目标调整后显示“按原目标”和“按调整后目标”的可追溯记录。
3. 累计型同时计算年度认定量、五年累计认定量、未弥补缺口和后续补位量。
4. 增长率型执行年度结算与五年总周期结算；年度与总周期均显示基期值、报告期值、增长量和增长率。
5. 核算失败时保留已审核业务事实，将指标标为“待补充核算口径”，不得将失败结果显示为 0 或已完成。

具体公式和不同指标类型的达成规则见 [第 6 章](#rules)。

### FR-11 待办与过程通知（P0）

通知服务于核心闭环，不扩展为独立消息中心。平台在列表和登录后的待办区呈现以下事项：

| 事件 | 接收人 | 待办结束条件 |
| --- | --- | --- |
| 学院任务下发 | 对应学院负责人 | 学院接收或校级撤销 |
| 填报提交／退回后重报 | 校级项目负责人 | 形成审核结论或学院撤回 |
| 审核退回 | 对应学院负责人 | 重新提交；是否长期保留已读记录不影响版本留存 |
| 跨院划转待确认 | 当前顺序中的学院负责人 | 确认、退回或发起人撤回 |
| 跨院划转待终审 | 有权限的校领导 | 批准、退回或发起人撤回 |
| 年度目标已认定未达标 | 校级项目负责人及本学院负责人 | 仅提示；完成顺延或后续补位后更新关联状态 |

通知包含计划、指标、年度、状态和业务入口，不通过消息正文修改任何业务数据。站外短信、邮件或即时通讯集成不在已确认范围内 TBD。

### FR-12 全链路操作日志与按时间导出（P0）

1. 记录计划发布、指标量化、学院任务下发／接收／撤销、填报提交／撤回、材料上传、审核、顺延、补位、划转、确认、审批和权限变更等关键操作。
2. 日志字段至少包括操作时间、操作人、角色、所属计划、对象层级、对象名称、动作、业务原因、调整前摘要、调整后摘要和关联单据。
3. 支持按开始时间、结束时间筛选，并可叠加计划、学院、对象和操作类型；导出范围不得超出当前用户数据权限。
4. 导出文件记录筛选条件和导出时间。导出格式 TBD；日志保留期限 TBD。
5. 普通业务用户不得修改或删除日志。日志导出本身也记入日志。

### FR-13 基础组织与业务字典维护（P0）

- 平台管理员维护四类角色、用户与学院／校级部门归属，以及用户是否在具体项目中担任校级或学院负责人。
- 维护指标类型、指标单位、建设年度和材料格式等字典；已被业务引用的字典项不可物理删除，只能停用并保留历史显示。
- 标准学院名录采用任务说明中的 10 个学院；别名映射用于导入，不在业务页面重复生成多个学院。
- 负责人变更需记录生效时间和交接人。历史填报、审核仍显示操作发生时的责任人，不回写为新负责人。
- 账号停用不删除历史记录；停用后不可继续操作，但已有待办须提示校级或管理员完成交接。

## 状态、计算与共享业务规则

跨模块只使用本章的一套定义，功能章节不另设相互矛盾的规则。

### 6.1 状态机

| 对象 | 状态 | 允许转换 | 关键限制 |
| --- | --- | --- | --- |
| 建设计划 | 草稿 → 已发布 → 执行中 → 已结项 | 发布后进入执行；结项条件 TBD | 已发布周期不可直接改；结项不删除历史。 |
| 学院任务| 草稿 → 待接收 → 执行中 → 已完成 | 接收前可撤销；接收后通过调整改变执行责任 | 全部必需里程碑满足完成条件后才可完成。 |
| 填报版本 | 草稿 → 审核中 → 已通过／已退回 | 审核中且无结论时可撤回至草稿；已退回可另建版本重报 | 旧版本只读；每次提交产生新版本号。 |
| 年度里程碑 | 未开始 → 待填报 → 填报中 → 审核中 → 已完成／已认定未达标／已退回 | 未达标可关联顺延或后续补位；退回后重报 | 上传材料不直接等于完成；必须有审核认定。 |
| 跨院划转单 | 待转出确认 → 待转入确认 → 待校领导审批 → 已生效 | 任一环节退回则已终止；终审前发起方可撤回 | 只有已生效才改变执行目标。 |

### 6.2 指标核算方式

| 核算方式 | 典型源表单位／示例 | 年度达成 | 五年结算与补位 |
| --- | --- | --- | --- |
| 累计型 | 项、个、门、本、人次；如五年建设 5 门在线精品课程 | 当年认定增量达到调整后年度目标 | 五年认定增量合计达到五年总目标；支持顺延和后续超额补位。 |
| 年度定额型 | %/每年、每年完成次数 | 每年独立达标 | 展示各年度达标情况，不默认用其他年度超额抵扣。 |
| 期末型 | 2030 年达到 15%、期末建成数量 | 阶段性里程碑按配置认定 | 以指定期末值结算；中期缺口不自动视为最终未完成。 |
| 比率型 | %、比值、每生比例 | 按同一分子、分母和统计时点计算并比较 | 不将各年百分比相加；需明确按年度、期末或五年整体口径。 |
| 增长率型 | 科研与社会服务到账经费五年增长 15% | 年度增长率与当年绝对值双显示 | 执行年度结算 + 五年总周期结算；先量化基期总量／增量。 |
| 是否型 | 制度建立、专项审计是否完成 | 审核认定“是”方可完成 | 按指定年度完成节点统计，不把“是”转换为数值与其他指标加总。 |
| 外部数据型 | 省厅统计、学校无需填写 | 依外部认定结果更新 | 来源、更新频率和责任人 TBD；不生成学院填报。 |

### 6.3 统一公式

`累计认定完成量 = Σ 已审核认定增量（草稿、审核中、已退回均不计入）`

`累计目标达成率 = 累计认定完成量 ÷ 调整后五年目标 × 100%`

`年度缺口 = max（调整后年度目标 − 当年认定完成量 − 已弥补量，0）`

`可补位余量 = max（当年认定完成量 − 调整后年度目标，0），仅适用于允许补位的累计型指标`

`年度增长率 =（本年度认定绝对值 − 上年度基期绝对值）÷ 上年度基期绝对值 × 100%`

`五年增长率 =（期末认定绝对值 − 周期基期绝对值）÷ 周期基期绝对值 × 100%`

- 目标方向为“不少于／不低于”时按 ≥ 判定；目标方向为“不超过／不高于”时按 ≤ 判定；精确值按 = 判定。
- 基期为 0 或分母为 0 时，不计算增长率或比率，显示“无法自动核算”，由校级补充口径。
- 达成率可显示超过 100% 的实际数值，甘特图条形长度 capped 至 100%，超额部分另标“超额 +X”。
- 计算保留原始精度，显示小数位和四舍五入规则 TBD；判断达成时不得因显示取反造成误判。
- 跨指标聚合只统计任务数、里程碑数和状态数，不把不同单位的目标值或完成值相加。

### 6.4 调整与审计的共同规则

- 所有调整均记录原目标、调整后目标、业务原因、发起人、生效时间和关联审批；禁止覆盖原始值。
- 待审填报、待确认调整与目标修改之间互斥，系统明确提示被占用的对象和数量。
- 关键动作（下发、提交、审核、撤回、顺延生效、划转确认与终审）需要明确确认；失败时不产生半生效状态，可基于原记录重试。
- 所有页面、导出与待办遵循同一权限范围；直接访问无权限对象时显示无权提示，不泄露指标内容。

#### 7.1.2 类型、空值与快照规则

- `DECIMAL(18,4)` 用于数量、人数、人次、百分比和金额等可计算值；百分比字段保存 `15` 表示 `15%`，不是 `0.15`。
- `TINYINT` 布尔值约定：`1=是／有效`、`0=否／无效`、`NULL=未填写`，三态不得混淆。
- `target_value_*`、`reported_value_*`、`recognized_value_*` 分别保存目标、学院填报和校级认定值；数值、布尔、文本三类字段按指标单位取值，非适用字段必须为 `NULL`。
- `*_raw` 字段保存 Excel 原始文本，永久保留；解析值与原文不一致时，以人工确认结果为准，但不得覆盖原文。
- `NULL` 表示未提供，`0` 表示数值零，`—` 表示不适用；三者必须分别保存。
- `*_snapshot_json` 保存动作发生时的完整目标或责任快照，用于原值与调整值双记录，不能用当前记录反向改写历史快照。
- 所有状态、类型、单位、核算方式保存稳定代码，中文名称由字典或枚举映射；已被引用的字典项只能停用，不能物理删除。
- 所有外键默认禁止因删除父记录而级联删除业务历史；草稿清理规则另行确定，不得影响审核、调整和日志记录。

### 8.1 初始化结果

1. 建立“智能生产装备与技术专业群”首个计划，周期为 2026—2030，归属建设目录与校级负责人待指定。

4. 已有专业群五年／2026 目标的字段进入待确认量化值，7 项空值保持未量化；学校整体目标独立保存。
5. 2027—2030 年仅将已有分工写入对应年度参考信息，其余保持空白，由校级负责人补录。

### 8.2 标准学院名录与别名

标准名录为：智能产业学院、游戏产业学院、数字金融产业学院、智能建造产业学院、数字影视传媒产业学院、现代通信产业学院、数据产业学院、未来技术产业学院、马克思主义学院（马院）、国际学院。

**导入前必须确认名称映射**

源表同时出现“大数据学院／大数据产业学院”“数据学院／数据产业学院”“现代通信学院”“数传学院”等简称或别名。平台可建议映射，但必须由有权限的用户确认；尤其“数据产业学院”和“大数据产业学院”不得未经确认自动视为同一主体。

### 8.3 必须在初始化评审中处理的数据情形

| 情形 | 源表例证 | 平台处理 |
| --- | --- | --- |
| 分配值与总目标不能简单求和 | 如来源序号 20、38 等 | 保留原文，标记分配待确认；禁止自动按括号值直接下发。 |

## 通用与非功能要求

只规定影响产品使用的质量边界，不限定技术实现方案。

| 类别 | 产品要求 |
| --- | --- |
| 权限与隐私 | 所有列表、详情、材料预览、甘特图、日志和导出执行一致的数据权限；学院不可通过链接访问其他学院未授权材料。 |
| 审核可用性 | 目标、填报、材料和审核动作在同一审核上下文中可达；常见材料在线预览失败时明确提示原因并允许重新上传，不强制下载审核。 |
| 数据一致性 | 下发、提交、审批等动作避免重复生效；重复点击或超时重试不得生成重复任务、重复审核或重复划转。 |
| 草稿与恢复 | 文本草稿与材料上传状态清晰分离；上传失败、页面刷新或审核退回后，不丢失已确认保存的内容。 |
| 可理解性 | 状态不仅依靠颜色；所有数值显示单位、年度和目标版本；空值、0、不适用及无法核算使用不同文案。 |
| 可追溯性 | 任何当前目标均能追溯到原目标与调整链，任何认定完成值均能追溯到填报版本、材料和审核人。 |
| 终端与性能 | 优先支持桌面端管理场景；浏览器范围、材料预览大小、并发量、响应时间和可用性指标 TBD。 |
| 数据保留 | 建设周期内保留完整版本、审核、调整与日志；周期后的保留和归档年限 TBD。 |
