# 全面功能审计与测试验证报告

- 审计日期：2026-10-30
- 审计对象：福州软件职业技术学院五年计划指标管理平台
- 测试环境：前端 `http://localhost:5173`，后端 `http://localhost:8080`，MySQL `metrics_db@13306`
- 数据基线：2 个正式计划、128 项 A 类指标、302 条 B 类任务、1510 条任务年度记录
- 结论：本轮发现的阻断、高、中等级问题均已修复并完成回归；未残留已知的 P0/P1 功能异常。指标总表点击 A 编号展开 B 的功能在 Chromium、Edge 及多尺寸视口下稳定可用。

## 一、审计范围与方法

1. 页面与入口：登录、计划列表、计划概览、指标总表、指标详情/甘特图、分解下发、学院工作台、任务填报、审核中心、调整申请与审批、统计报表、待办与消息、模板管理、操作日志、系统管理、可视化大屏。
2. 业务链路：计划创建 → 指标及年度目标 → A→B 分解与守恒 → 下发 → 启动及年度激活 → 学院接收 → 填报及材料 → 校级审核 → 调整申请及审批 → 年度核算 → 待补做 → 已补做 → 统计及大屏。
3. 非功能检查：服务端数据范围、乐观锁与幂等、文件完整性、并发刷新、跨计划慢响应、请求并发、大量 B 数据、异常重试、移动端与触控适配、控制台错误、横向溢出。
4. 验证方式：静态代码复核、JUnit 5、Vitest、TypeScript 与生产构建、真实 API、Playwright 真实 UI 全链路、网络 mock 边界测试、数据库清理后基线核验。

严重等级定义：P0 为越权、数据损坏或主流程阻断；P1 为核心数据/状态错误及重要功能失效；P2 为交互、性能和可维护性问题。

## 三、代码质量、性能与安全优化

### 3.1 质量与结构

- 移除已退出新流程的独立 A+ 分解向导及重复逻辑，指标详情、指标总表、工作台和调整页围绕统一 A→B 结构分层。
- 将主体统计、甘特展示、填报元数据、调整试算与待办深链等重复判断收敛到 `frontend/src/utils/`，并补对应 Vitest。
- 后端核心计算继续使用 BigDecimal；补齐 DTO 契约、请求 version、数据范围守卫和明确错误明细。
- 清理无效接口封装和重复视图分支，保留历史 A+ 只读兼容，不引入新技术栈或无关重构。

### 3.2 性能

- B 的五年目标在任务列表装配阶段一次性返回，避免逐 B 查询详情；125 条 B 通过 100+25 两页读取，非 125 次详情请求。
- 同一 A 的展开请求去重，重复展开使用缓存；全部展开 worker 并发上限为 6。
- 计划切换使旧请求失效，避免慢响应回写和无效应答渲染；无激活年度减少 1 次重复统计请求。
- 保留已实施的设备条件渲染和菜单点击挂载优化，不重新引入双套表格/卡片同时渲染。

### 3.3 安全与一致性

- 下发、里程碑、文件、审核、调整、填报均复核服务端权限，前端菜单不作为安全边界。
- refreshToken 原子旋转，审核乐观锁，敏感代填/代审原因非空，写操作继续使用幂等与审计。
- 分片文件核验真实大小、魔数和哈希；所有按 ID 的关键资源访问按数据范围拒绝越权。
