## 已确认问题

### 1. [P1] 填报和调整可以绑定无权访问的文件

位置：[SubmissionService.java:427](../backend/src/main/java/edu/fzrj/metrics/module/submission/service/SubmissionService.java#L427)、[AdjustmentService.java:1180](../backend/src/main/java/edu/fzrj/metrics/module/adjustment/service/AdjustmentService.java#L1180)。

绑定逻辑仅确认 `file_info` 存在，没有校验上传者、原业务访问权或当前操作人是否有权使用该文件。知道他人的文件 ID 后，可将其绑定到自己的填报/调整；`FileService.requireReadable()` 随后会通过新业务引用授予访问权。TEMP 文件也能被他人绑定为 BOUND。

复现：当前用户 99，对上传者 888 的 BOUND 文件 777 调用同一绑定方法，成功插入 `file_ref`。建议集中实施文件绑定授权，先校验再建立引用，不能让建立引用本身成为授权来源。

### 2. [P1] 未配置环境变量时仍接受公开的签名密钥默认值

位置：[application.yml:48](../backend/src/main/resources/application.yml#L48)、[application.yml:55](../backend/src/main/resources/application.yml#L55)、[JwtService.java:25](../backend/src/main/java/edu/fzrj/metrics/security/JwtService.java#L25)、[SignedUrlService.java:81](../backend/src/main/java/edu/fzrj/metrics/module/file/service/SignedUrlService.java#L81)。

JWT 和文件 HMAC 密钥均有仓库中可见的固定回退值，且没有启动校验。环境变量遗漏时服务仍可启动；知道默认值的人可伪造指定用户 ID 的 Token，或构造公开 raw 文件接口接受的签名。该问题的触发条件是未覆盖默认配置；本轮未读取或判断实际部署密钥。建议启动时拒绝缺失或占位密钥，开发测试配置单独提供。

### 3. [P1] BOOLEAN 调整遇到正常的空年度目标时抛空指针

位置：[AdjustmentService.java:948](../backend/src/main/java/edu/fzrj/metrics/module/adjustment/service/AdjustmentService.java#L948)。

`indicatorTargets()` 使用 `Collectors.toMap(...getTarget...)`，不接受 null value。BOOLEAN 非计划完成年的目标按契约正是 null，因此延期试算/申请或目标调整读取年度目标时就会 NPE，尚未进入已修复的“BOOLEAN 不求和”分支。

复现：Mapper 返回一条 `year=2026,target=null` 的合法年度目标，直接调用该方法得到 `NullPointerException`。应使用允许 null 的 Map 填充方式，并覆盖完整 BOOLEAN 年度序列的服务测试。

### 4. [P1] MANUAL 的 STOCK/GROWTH 统计与年度核算仍未正确使用总量

位置：[StatsService.java:421](../backend/src/main/java/edu/fzrj/metrics/module/stats/service/StatsService.java#L421)、[SettlementService.java:498](../backend/src/main/java/edu/fzrj/metrics/module/stats/service/SettlementService.java#L498)。

前轮修复已让人工认定写入 `actual_total`，但统计树 MANUAL 分支仍构造 `total=null` 的 `YearResult`；STOCK/GROWTH 的完成率和达标判定读取 total，导致树接口的年度完成率为空。年度核算的 MANUAL 分支同样丢弃 total，并通过缓存写入将已认定的 `actual_total` 清空。

复现：目标 100、人工认定及持久化总量均为 80，统计树返回 `actualTotal=80, completionRate=null, cumulativeRate=0.8`。应统一认定、查询、核算三个入口的口径结果构造。

### 5. [P1] 数量填报与审核认定允许负数

位置：[SubmissionValueRules.java:25](../backend/src/main/java/edu/fzrj/metrics/module/submission/service/support/SubmissionValueRules.java#L25)、[SubmissionDtos.java:26](../backend/src/main/java/edu/fzrj/metrics/module/submission/dto/SubmissionDtos.java#L26)。

校验仅检查字段是否存在、是否符合口径，未限制数量字段下界；DTO 与数据库也未提供非负兜底。`INCREMENT amount=-5` 可以通过校验，审核将正填报 5 认定为 -5 也被视为合法核减。负完成值随后参与累计和剩余额度计算，可抵消已有完成量并扩大可调整量。

复现：负增量字段校验返回 null；`exceedsSubmitted(提交5,认定-5)` 返回 false。应按口径分别校验采集值与认定值，不能只检查“认定值不大于填报值”。增长率计算结果允许为负，与数量原始值的校验应区分。

### 6. [P2] 删除 A 或改为不可量化时留下 B 草稿

位置：[IndicatorService.java:425](../backend/src/main/java/edu/fzrj/metrics/module/indicator/service/IndicatorService.java#L425)、[IndicatorService.java:354](../backend/src/main/java/edu/fzrj/metrics/module/indicator/service/IndicatorService.java#L354)。

删除只检查下级 A+ 和已生效范围，再软删指标与年度目标；待下发 B 不阻止删除，也未同步软删。改为不可量化的判断同样仅考虑 A+。新流程允许 A 直接有 B，因此正常草稿分解后删除/转换 A，会留下指向已删除或不可量化 A 的任务和年度行，学院列表与后续分解出现残留。

应明确拒绝该操作，或在同一事务中清理尚未下发的 B 及关联结构；已执行数据继续保持保护。

### 7. [P2] 模板/复制计划更换周期时丢失年度目标

位置：[PlanService.java:603](../backend/src/main/java/edu/fzrj/metrics/module/plan/service/PlanService.java#L603)、[PlanService.java:504](../backend/src/main/java/edu/fzrj/metrics/module/plan/service/PlanService.java#L504)。

实例化和复制分工均按来源的绝对年份写入，并直接跳过新周期以外的年份。2026—2030 的结构用于新建 2031—2035 计划时，所有年度目标被跳过；复制 B 时还可能生成没有年度行的任务。

复现：将五个来源年度目标交给 2031—2035 的实例化方法，年度目标插入次数为 0。应提供相对年份映射或明确拒绝不支持的周期变换，不能返回一份静默丢失目标的新计划。

### 8. [P2] 材料库与已上传清单未落实多角色数据范围并集

### 9. [P2] 默认统计年度落到规划末年

### 10. [P2] 多处乐观锁更新失败仍返回成功

### 11. [P2] 五年核算后解锁年度不能恢复一致的执行状态

### 18. [P1] 年度核算允许覆盖审批中调整并锁死审批入口

位置：[SettlementService.java:118](../backend/src/main/java/edu/fzrj/metrics/module/stats/service/SettlementService.java#L118)、[AdjustmentDecisionService.java:118](../backend/src/main/java/edu/fzrj/metrics/module/adjustment/service/AdjustmentDecisionService.java#L118)。

核算仅拒绝待审核填报，没有检查未结束调整或被冻结额度。核算会覆盖 task_year 的 ADJUSTING 状态并锁定年度；调整审批入口在任何 APPROVE/REJECT 写入之前统一拒绝锁定年度。因此申请仍待审批、额度仍冻结，却不能通过也不能驳回，只能另行撤回或解锁处理。

应在核算前拦截相关在途调整，或在明确规则下终止并释放冻结；检查与锁定还需处于一致的事务边界。

### 19. [P2] 未来年度可以提前核算锁定

位置：[SettlementService.java:100](../backend/src/main/java/edu/fzrj/metrics/module/stats/service/SettlementService.java#L100)。

年度核算只检查计划 ACTIVE、年度 ACTIVE 和待审核记录，完全不检查年份或核算时间。当前所有规划年度默认 ACTIVE，故 2026 年可以直接核算 2030 年，提前生成未达标/补做并封锁未来填报。前轮新增的五年核算时间限制不覆盖此入口。

至少应拒绝未来年度核算，并按 PRD 的年度核算截止规则确定当前年能否正式结算，前后端使用同一规则。

## 尚未确认为缺陷的并发与快照风险

以下不计入 19 项确认问题，需补专项验证后定结论：

1. **并发审核与 MySQL 一致性读。** ReviewService 在任务年度行锁之前读取填报；AnnualTargetGuard 加锁后再用普通 SELECT 读取已通过记录。在 MySQL REPEATABLE READ 下，事务先前建立的快照可能使第二个审核仍看不到第一个审核提交的数据，需要真实双连接验证“6+6 对目标 10”能否绕过上限。不能只以 Mockito 验证调用了 FOR UPDATE。
2. **低于目标更好及 BOOLEAN 的并发重算。** 上限守卫对这些口径提前返回，未获取同一任务年度锁，而 ActualRecalcService 忽略更新失败。需要并发审核验证累计值、版本、审核结果和通知是否同时一致。
3. **审批期间接收目标变化后的快照语义。** `computeMoveAfter()` 用申请时 before 加本次移动量构造 after；接收任务可在期间收到其他调整。本次生效后的实际目标可能不等于该 after。应核对当前产品约定究竟要保存申请试算还是实际生效前后快照，并用两个交叠转移申请验证。

## 修复顺序

1. 先处理文件授权、签名配置、BOOLEAN 空指针、负数量及 MANUAL 核算口径。
